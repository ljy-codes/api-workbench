## Windows 安装版

运行 `EnvDock-1.0.0-windows-x64-setup.exe`，按提示安装。安装与卸载采用深色向导，欢迎页列出功能概要。仅为当前 Windows 用户安装，不需要把数据库放入程序目录。

- 默认程序目录：`%LOCALAPPDATA%\EnvDock`（可在安装向导修改）。
- 开始菜单：`EnvDock` 文件夹。桌面快捷方式可在安装向导完成页选择。
- 数据目录保持 `%LOCALAPPDATA%\ApiWorkbench`，是为兼容已有版本特意保留的内部名称。升级不覆盖业务数据库，卸载默认保留该目录。
- 初次安装不会自动读取 Yaak 或旧便携版的数据；新用户得到空工作区。
- 系统需有 Microsoft WebView2 Runtime；没有时安装器会下载并安装，**此步骤需要联网**。应用不把接口配置或请求响应上传到云端。
- **2026-10-04 安装修订，版本仍为 1.0.0**：新装、重装和升级都会检测 WebView2；缺失时自动尝试微软在线引导安装器，失败后转为官方完整安装器，并进行有界重试、微软签名验证与安装后重新检测。详情中显示检测、下载及安装状态。
- 依赖准备成功前不移除旧版程序；全部自动尝试失败后才提供重试、微软手动安装页面或退出选项。静默/被动安装返回非零错误码；要求重启或安装超时时停止继续启动依赖安装，避免并发安装。
- 不要求用户安装 Node.js、Rust、编译器或 SDK。只补齐实际运行依赖，不下载替换 Windows 系统 DLL；系统不受支持、系统组件损坏或企业策略限制需要用户处理。
- 当前未做代码签名，发布者可能显示为未知；请核对来源和 `SHA256SUMS.txt`，遵循本机安全策略，不要关闭安全防护。
- 仅通过安装器卸载/替换程序，不要把包含业务数据的目录选作安装目录。

### 从旧便携版迁移

先在旧版保存并关闭所有 EnvDock / 接口工具实例，**在首次启动安装版之前**，以同一个 Windows 用户运行随包提供的脚本：

```powershell
.\migrate-local-data.ps1 -SourceDirectory 'D:\专用工具\接口工具\运行目录\ApiWorkbenchData' -ConfirmSameWindowsUser
```

源目录不会删除；脚本先备份并校验，再复制数据库及存在的 SQLite WAL/SHM 文件。源目录历史 `backups` 不合并，仍原样留在旧目录。目标已有数据库时拒绝覆盖，不能将两份工作区简单合并。遇到此情况，请先分别备份并通过应用项目导入功能合并，或人工确认选用哪份数据，切勿直接覆盖。

`-ConfirmSameWindowsUser` 表示确认来源是本机当前 Windows 用户的数据，不是自动解密校验。迁移只适用于同机同 Windows 用户；DPAPI 凭据跨用户/电脑不能保证解密。运行中不要手工只复制 `app.db`。迁移脚本返回的 `BackupDirectory` 是目标目录外的独立恢复副本，卸载不会扫描删除它；确认不再需要时，请按返回的准确路径自行处理。

### 卸载与完整清理

在 Windows「已安装的应用」中卸载 EnvDock，或运行安装目录的 `uninstall.exe`：

- **默认保留数据**：移除程序、快捷方式及本软件安装注册项，保留本地工作区。
- **完全卸载**：勾选“同时删除本地工作区数据”并二次确认，清理下面三个应用专属目录，包括接口、环境、凭据、请求/响应、缓存、日志和目录内的自动备份：
  - `%LOCALAPPDATA%\ApiWorkbench`
  - `%LOCALAPPDATA%\local.apiworkbench.desktop`
  - `%APPDATA%\local.apiworkbench.desktop`
- **升级保留数据**：升级中的卸载不会执行数据清理，即使误传清理参数。
- **不误删其他文件**：不删除 Yaak、旧便携版目录、上述数据目录外的手动导出与迁移恢复副本、共享 WebView2 或安装目录中的其他文件。选择完整清理意味着上述三个数据目录内的所有内容均会移除，不要把唯一备份存于其中。
- 清理前检查目录链接和文件占用；失败会停止卸载并保留程序及卸载入口。删除不是事务，权限或并发变动仍可能导致部分清理，重试前请关闭程序并检查提示；重要数据务必先导出到其他目录。

管理员自动化可用 `uninstall.exe /S` 保留数据；**仅独立、大小写精确的 `/PURGE` 参数授权删除数据**，即 `uninstall.exe /S /PURGE`。不要以 SYSTEM 或其他 Windows 用户运行。`/PURGE=0` 等变体不触发清理。交互确认框与系统目录选择器由 Windows 绘制，可能跟随系统主题而非安装器主题。

## 基本模型

项目 → 服务 → 目录/接口。环境作为项目级运行配置，服务在每个环境单独配置基础地址。接口名称、请求方法和路径共用；Query、Headers、鉴权、正文、表单及超时按接口 × 环境独立保存。切换环境不复制接口。

服务基础地址统一在「环境矩阵」维护，变量页的「配置服务地址」可直达；环境变量用于 token、用户 ID 等请求参数。加载旧工作区、导入集合以及编辑变量时，会合并同项目、同环境、同地址且无模板引用的非秘密环境变量，避免重复维护。旧数据合并后先保留为草稿，按原保存流程落盘；保存失败仍保留草稿。

已被请求或其他配置引用的历史地址变量、秘密值及其他作用域变量继续保留。兼容保留的地址变量仍按普通变量使用，不会随环境矩阵自动同步；变量页会提示保留原因。异常地址或重复名称配置不自动合并。

运行数据由 Rust 使用 SQLite 保存；敏感变量通过 Windows DPAPI 保护。无账号、云同步、遥测、远程日志或自动更新。

## 开发启动

要求 Node.js、Rust MSVC 工具链、MSVC C++ Build Tools、Windows SDK 和 WebView2 Runtime。

脚本优先使用本项目 `.tools` 下的隔离 Rust；没有隔离工具链时使用 PATH 中的 Rust。Git 仓库不包含工具链和依赖缓存。请先安装 Node.js、Rust MSVC 工具链，以及包含 C++ 桌面开发组件的 Visual Studio Build Tools / Windows SDK。脚本只修改当前进程环境。

```powershell
cd D:\专用工具\接口工具\开发空间
npm ci
.\scripts\dev.ps1
```

仅查看前端：

```powershell
npm run dev
```

访问终端显示的本机地址。浏览器模式是**仅内存工作区预览**，不支持实际持久化接口数据或发送请求。主题与布局偏好单独保存在本机 localStorage，业务工作区仍由桌面版 SQLite 保存。

## 1.0 核心能力

- 按环境隔离请求配置和最近一次响应；域名继续按服务 × 环境配置。
- 切换项目、环境、接口、关闭接口标签前自动保存，支持 Ctrl/Cmd+S；发送和预览前自动保存，不反复确认。保存失败保留草稿并停止切换；生产发送确认仍保留。
- 项目、环境支持预设色和自定义 #RRGGBB；下拉使用深色背景和高对比文字，颜色只作辅助标记。
- 响应缓存按接口 × 环境只保留最近一条，Windows DPAPI 加密保存，不导出到项目文件。
- 工作区管理提供数据清理：默认清全部项目的响应缓存；可勾选清空所有请求正文和表单内容。接口定义、域名、Query、Headers、鉴权及变量保留，操作需再次确认。
- 响应缓存限额为 64 MiB 序列化数据，自动淘汰最旧缓存；不是整个数据库或备份目录限额。手动清理后执行数据库压缩与 WAL 回收。手工备份不自动删除。
- 请求正文是配置，不按时间自动过期。旧版共用配置仅作为缺省模板，各环境首次编辑后独立。

## 工作台基础能力

- 紧凑工作台：正文类型与请求配置合并为一行，服务域名悬停查看；预览、cURL 和超时设置位于右侧“更多请求操作”。
- 左下角「设置」统一管理外观、布局、导入导出和本地数据。支持浅色、深色和跟随系统，主题启动前应用，所有偏好仅在本机保存。
- 右上角可收起/展开侧栏、切换请求与响应上下/左右分屏；尺寸和布局自动记住。侧栏与分隔线支持拖动及键盘调整，布局切换保留当前编辑内容。
- 请求与响应统一 JSON 分色：字段名蓝色、字符串橙色、数字青色、布尔值与 null 紫色。响应正文只读，支持行号、折叠和键盘选择。
- 多请求标签页：右侧「关闭全部」一键关闭当前项目标签；关闭前自动保存，保存失败保留标签和草稿。关闭标签不删除接口、草稿或响应，不取消进行中的请求。
- 接口集合标题栏支持一键收起全部服务与目录，同时清除搜索。右键服务、目录或接口可快捷添加目录/接口，自动填入所在服务和目录，保留当前编辑内容。
- 当前项目接口搜索：名称、路径、方法、服务名；面板支持拖动和键盘调整。
- 服务公共 Headers；按变量展开后的名称匹配，接口同名 Header 覆盖服务同名组（ASCII 大小写无关），接口重复 Header 保留。
- 请求鉴权支持继承服务、无鉴权、Bearer、Basic、API Key（Header / Query）。
- JSON、文本、URL 编码表单与 multipart 文件上传。
- 原生变量解析预览：查看最终脱敏 URL、变量来源和覆盖结果。
- 响应格式化、文本搜索；点击放大镜或在响应区按 Ctrl/Cmd+F 展开搜索，Esc 收起。只显示文本，不执行响应中的 HTML/脚本。
- cURL 解析导入、脱敏 cURL 复制；自动识别接口集合文件，按项目和环境勾选导入/导出，一致性 SQLite 备份。
- 底部状态栏显示 `著作:lxs`。

### 凭据与文件

鉴权的 Token、密码、API Key 值只填写完整变量引用，例如 `{{accessToken}}`。实际值到变量配置中填写并**勾选“敏感”**，才会由 DPAPI 加密保存；普通变量、普通 Headers 和 Body 不自动加密。引用本身不等于加密。

请求 `auth=null` 继承服务；显式“无鉴权”禁用继承。鉴权生成的 Header / Query 与手工参数同名时拒绝发送，避免悄悄覆盖。

文件须通过本地选择器明确选取；单文件最多 10 MiB，总文件内容最多 20 MiB。只接受普通文件，不接受符号链接/重解析点。请求前预览和复制 cURL 不读取文件。导入项目中的文件路径会清空、文件项禁用，需重新选择。

### 数据交换

「设置 → 导入导出」或「工作区管理」可读取文件，也可粘贴 JSON/YAML。文件最大 10 MiB，仅在本机解析；不会执行脚本、动态函数或发起请求。先预览，再勾选项目和环境，确认后分配全新 ID 合并为草稿，不覆盖已有项目；可按 Ctrl+S 或切换上下文时保存。

支持 EnvDock 原有单项目 v1/v2 JSON、新多项目 JSON、Postman Collection v2.0/v2.1、Postman Environment，以及 Yaak 官方工作区 JSON 和包含完整引用模型的 YAML。目录、HTTP 请求、常用正文/鉴权及变量会转换；环境继承会展平。不支持的脚本、动态模板、WebSocket/gRPC 等给出提示，不承诺所有第三方扩展兼容。单独导入的 Postman Environment 会成为独立新项目，不自动合并到既有集合；Yaak 同步 YAML 需包含被引用的工作区和父模型。

导出为普通多项目 JSON（`envdock-transfer` v1），可选择每个项目的环境；未选环境的域名绑定、变量和独立请求配置一同移除。只选项目、不选环境时，保留接口结构及共享配置。响应缓存不导出，已知凭据脱敏，本地文件路径清空并禁用。此多项目包需当前新版读取，旧版仅支持单项目交换文件。

cURL 导入要求先选项目与环境，生成新服务及其当前环境绑定，不改变现有服务地址。

只解析支持的 cURL 语法，**绝不执行命令**；不支持的参数会明确报错。导出的 cURL 是 POSIX shell 格式，不是 PowerShell 命令，敏感值与文件路径为占位内容，使用前需手工补齐。

cURL HEAD 使用 `--head`；HEAD 同时配置正文时拒绝导出，避免生成 cURL 无法执行的参数组合。导入导出不能保证签名 URL 的原始字节完全不变，此类请求请人工核对编码。

项目交换默认移除敏感变量值和已知凭据参数，导入后需重新填写。**自由格式 Body、自定义 Header、普通变量仍可能包含业务隐私，导出前必须人工检查。** 项目交换文件不是完整凭据备份。

## 数据目录与升级

- 常规构建：`%LocalAppData%\ApiWorkbench\app.db`。
- `portable` 构建：EXE 旁 `ApiWorkbenchData\app.db`。
- `app.db-wal`、`app.db-shm` 是 SQLite 工作文件，运行中不能仅复制主数据库当备份。
- 1.0.0 沿用开发阶段的 schema v3，应用版本号与数据库格式版本互相独立。首次打开 v1/v2 数据库前，自动以 SQLite backup API 在数据目录 `backups` 下生成一致性备份，然后事务迁移；备份失败停止升级，未知版本拒绝打开。
- 工作区管理中的备份按钮只备份**已保存**数据，不含当前草稿。备份文件包含普通配置明文和 DPAPI 密文，需要按私有文件保护。
- 回退：关闭所有实例，单独保留完整 v3 数据目录；把升级前备份恢复到另一个目录，配合对应旧版本程序使用。不要直接用旧程序打开 v3，也不要执行 DROP/手工降级；环境配置和响应缓存无法无损转换为旧版。
- 跨电脑或 Windows 用户后 DPAPI 凭据可能无法解密，需要重新输入，不会明文兜底。

## 当前操作方式

点击左上角 EnvDock 图标可进入仪表盘主页，查看当前项目的接口、服务、环境和目录数量，以及服务分布、HTTP 方法分布和环境地址配置覆盖。从「继续调试」可返回已打开接口；主页也提供新建接口、环境配置、变量与工作区管理入口。环境覆盖仅表示本地配置，不代表服务可达。

1. 新建项目和环境。
2. 新建服务，打开环境矩阵填写各环境基础地址。
3. 新建接口，填写方法与相对路径，例如 `/users/{{userId}}`。
4. 配置变量、Query、Headers、鉴权或请求 Body。
5. Ctrl+S 可立即保存；切换接口/环境以及预览、发送时会自动保存。
6. 查看状态码、耗时、已接收大小、Headers 与响应正文。

生产环境发送需明确确认。没有环境绑定时禁止发送；取消仅停止客户端等待，不代表服务端撤销操作。

## 当前限制

- 请求引擎先支持 HTTP/1，不支持系统代理或可配置代理；TLS 校验开启，不能跳过证书校验。
- 不自动跟随重定向，不自动重试。仅保留每个接口 × 环境最近一次响应，不保存完整执行历史。
- 响应正文预览上限 2 MiB，越界后停止继续接收；“已接收大小”不代表完整响应大小。非 UTF-8 字节以替代字符展示，不适合二进制下载。
- JSON 变量只支持字符串值，不支持键名或裸 JSON 结构占位符。
- 尚无 OAuth 流程、完整历史、OpenAPI 导入、备份恢复 UI、脚本、接口串联和批量测试。
- 设置和转换模块按需加载；第三方格式解析器不进入首屏主包。尚未完成桌面启动耗时与峰值内存的定量基准，不能据此承诺具体性能指标。
- 数据格式与 IPC 尚处开发阶段；不要把当前唯一副本的生产凭据或重要请求集只存于此工具。

## 安装包与便携预览构建

安装包（优化的 release 构建，不启用 portable feature）：

```powershell
.\scripts\build-installer.ps1
```

输出 `publish\EnvDock-1.0.0-windows-x64\EnvDock-1.0.0-windows-x64-setup.exe`，同时提供说明、可选迁移脚本及 SHA-256 校验和。打包只取程序、前端资源和安装器组件，不内置测试项目、数据库、Yaak 内容或凭据。首次构建 NSIS 工具链可能需要联网。主题插件由仓库内 C++ 源码使用 MSVC x86 工具链编译，不依赖下载第三方换肤插件。

图标为原创矢量几何图形，源文件 `public/envdock.svg`；`python scripts/generate-brand-assets.py` 可重新生成 PNG、多尺寸 ICO 和安装器位图（仅资产制作需要 Pillow）。修改 NSIS 时应对照 `src-tauri/installer/UPSTREAM.md` 更新并运行参数和清理测试。

便携预览版：

```powershell
.\scripts\build-preview.ps1
```

输出 `publish\EnvDock-1.0.0-portable-preview`，包含 `EnvDock.exe`、说明和 SHA-256 校验文件。是未签名的 debug 开发预览构建，需要本机已有 WebView2 Runtime；不内置在线更新。直接运行 EXE 即可，数据保存在 EXE 旁的 `ApiWorkbenchData`。

本机回环验收服务（可选）：

```powershell
node scripts/smoke-server.mjs
```

仅监听 `127.0.0.1:18765`，可使用 `/health`、`/echo`、`/delay` 路径，不需要外部业务服务器。
