# 云同步独立验证原型

日期：2026-10-27。**本目录不是已上线功能，没有接入 EnvDock 主程序，也没有安装云同步组件。**

本轮用虚构工作区和本地 WebDAV 服务，验证用户提出的“首台电脑选文件夹上传、另一台电脑选该文件夹接入并持续共用”的协议可行性。

## 运行

在源码目录执行，开发环境使用 Node.js 24.15.0，不需要添加 npm/Cargo 依赖：

```powershell
node --test experiments/cloud-sync/cloud-sync.test.mjs
node experiments/cloud-sync/demo.mjs
```

服务仅监听 `127.0.0.1` 的临时端口，程序结束即关闭。测试和演示不读取真实数据库、账号、Cookie、Token 或浏览器状态，不请求真实接口。

演示会把虚构设备文件写入 `.tmp/cloud-sync-probe-20261027/demo/`，其中 `result.json` 记录每步结果，`device-b-imported.json` 证明第二设备能获取和落盘保持原 ID 的配置。它不表示已经向主程序数据库导入。

本轮结果：**20 项端到端测试通过，0 项失败；双设备演示 5 步完成。** 测试日志为 `.tmp/cloud-sync-probe-20261027/test.log`，演示日志为同目录 `demo.log`。

## 本轮可验证行为

- 创建目录、选择已有目录、枚举可选子目录。
- 第二设备从同一目录读取配置，重复接入不复制项目或分配新 ID。
- A 修改 B 拉取、B 修改 A 拉取、无变化时不上传。
- 敏感变量值、本地文件路径和活动项目/环境不进入共享配置；原输入对象不变。
- 配置在本机加密后上传，公开识别文件经 HMAC 验证。
- 密码错误、密文/头文件篡改、认证失败时停止接入。
- 先写不可变快照，再条件更新当前版本；上传失败时上一版本仍可读取。
- 断网仍能保留本地修改；提交成功但响应丢失时，重新同步能识别已提交版本。
- PUT 仅认可明确完成的 200/201/204；返回 202 已受理时不推进基础版本、不发布尚未完成的快照。
- 两端同时修改（含删除）时保留本地草稿与可读取的远端版本。
- 实际通过反例请求检测 `If-Match`、`If-None-Match`，拒绝仅返回 ETag 却忽略写入条件的服务。
- 拒绝远程 HTTP、URL 内嵌凭据、跨级路径、缺少强 ETag，以及加密后超过 2 MiB 的文件。

## 主程序兼容性与剩余风险

本轮所有新增代码在 `experiments/`，没有应用入口引用；`package.json`、锁文件、Cargo 配置、Tauri 配置、主程序源码及原有未提交改动均不因本轮试验而变化。版本仍为 1.0.0。不会增加现有安装包或运行进程。

原型使用全量配置快照，暂不做逐字段自动合并；冲突结果交回调用者保留双方版本。加密快照上传后若发布当前版本失败，可能留下未引用快照；正式组件需要保留策略与垃圾清理。

只读代码审查曾发现“202 已受理被误判为写入成功”，可导致本地修改被旧版本替换。本轮已补充快照上传和当前版本发布两项回归用例，先确认失败，再修复状态判定，20 项测试通过。审查者已定向复跑两项用例并确认问题关闭。

原型只针对当前测试夹具验证 XML 目录响应，未覆盖所有 WebDAV 实现；工作区校验也不等同于现有完整的应用导入边界。正式功能必须复用/提取现有字段、引用及规模校验，接收远端数据后先预览，再通过应用事务落盘。

正式按需组件还需要：独立可执行文件打包、受信任下载清单与签名、断点/失败处理、版本兼容检查、凭据存储、同步 UI、草稿保护、重试调度、撤销授权及真实服务验收。开发机上的 Node.js 不能成为最终用户的前置要求。

## 建议落地顺序

1. WebDAV 可选组件：不需要为工具申请网盘 OAuth 应用，先完成真实服务验收和主程序接入。
2. 百度适配器：先申请应用并验证目录范围、回调以及双机令牌生命周期。
3. 夸克适配器：先确认桌面集成许可和原生 Windows 支持，不依赖逆向 Cookie 方案。
