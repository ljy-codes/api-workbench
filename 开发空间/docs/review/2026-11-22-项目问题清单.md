# EnvDock 项目问题清单

审查日期：2026-11-22。审查对象：`接口工具`（EnvDock / api-workbench 1.8.1）当前 `main`。
环境：macOS 13.7.8 Intel、Node 25.6.0、npm 11.8.0。

## 审查方式

- 通读 README、发布说明、macOS 说明与设计文档，对照实际目录、标签和构建产物。
- 阅读前端入口、`useWorkbench`、主题、对话框、IPC、Rust 存储与请求传输实现。
- 执行：`npx tsc -b`、`npx vitest run`（默认与关闭 Node Web Storage 两种）、`npm run test:packaging`、`npm audit --omit=dev`、`sh scripts/mac.sh test`（Rust 测试挂起，用 `sample` 定位到钥匙串）。
- 计算三套现有主题关键前景/背景的 WCAG 对比度。

结论：**没有发现数据泄露或请求执行层面的高危漏洞**；主要风险集中在「测试可信度」「交付记录一致性」「可维护性」三处。

如果只做三件事，按顺序是：

1. **让 `npm test` 默认可信**：固定 Node 22 LTS 或修复测试环境的 `localStorage`（P1-1）。
2. **隔离 macOS 钥匙串并补最小 CI**：Rust 单测改为内存密钥后端，再跑 Node 测试 + `tsc` + Rust 测试 + 打包断言（P1-4、P1-3）。
3. **对齐交付记录**：补 `v1.8.1` 标签或改正 README，并消除 macOS 交付描述矛盾（P1-2）。

## 详细说明

### P1-1 测试在默认 Node 25 下大面积失败

`npm test`（Node 25.6.0）结果：

```text
Test Files  11 failed | 66 passed (77)
Tests       98 failed | 1003 passed (1101)
TypeError: localStorage.clear is not a function
❯ src/lib/preferences.test.ts:44:16
```

根因：Node 25 默认暴露实验性 `localStorage`（`typeof localStorage === 'object'`，但没有 `clear`），覆盖了 jsdom 提供的内存实现。`docs/macOS.md` 已记录规避方式
`NODE_OPTIONS=--no-experimental-webstorage npm test`，但根目录 README、`npm test` 默认命令和 `src/test/setup.ts` 都没有处理。

影响：新开发机或 CI 直接跑 `npm test` 会得到 98 个假失败，无法作为合并门槛；也容易让人误判业务代码损坏。

建议：

1. `package.json` 增加 `"engines": { "node": ">=20.19 <25" }`，并添加 `.nvmrc`（22 LTS）。
2. 或在 `src/test/setup.ts` 显式把测试环境的 `localStorage` 指回 `window.localStorage`，或在 vitest 配置中固定 `environmentOptions.jsdom.url` 并删除 Node 全局。
3. 增加 `test:ci` 脚本，显式带 `NODE_OPTIONS=--no-experimental-webstorage`，README 同步说明。

### P1-2 交付标签与文档不一致

- README「当前交付」写：GitHub Release 对应标签为 `v1.8.1`。
- 实际远端与本地标签：`v1.8.0`、`v1.8.0-macos`、`v1.8.1-macos`，**没有 `v1.8.1`**。
- README macOS 段写「本次没有生成新版 macOS 安装包」，但 `publish/EnvDock-1.8.1-macos-release/` 已有 x64 与 arm64 两个 `.dmg`，且 `BUILD-INFO.json` 记录 tag `v1.8.1`。
- `publish/` 只有 macOS 交付，README 却以 Windows x64 安装版为当前交付。

影响：外部用户按 README 找不到对应 Release；版本审计链（README → tag → BUILD-INFO）对不上。

建议：补建 `v1.8.1` 标签（指向 `f93d868`），或统一改成 `v1.8.1-macos` 的表述；README 的「本次未生成 macOS 安装包」改成「已生成 macOS x64/arm64 dmg，Windows 安装包由另一构建机产出」。

### P1-3 缺少 CI 与静态质量门

仓库没有 `.github/workflows`，`package.json` 没有 `lint` 脚本，根目录也没有 ESLint / Prettier / Biome / EditorConfig。当前质量完全依赖人工执行命令。

影响：P1-1 这类整类测试失败可以长期存在；格式、未使用变量、依赖升级没有自动检查；Rust 与前端测试没有统一入口。

建议：最小 CI 矩阵即可：

```yaml
# Node 22 / Ubuntu：npm ci && npm test && npm run build
# Rust：cargo test --manifest-path src-tauri/Cargo.toml
# Windows：npm run test:packaging
```

静态检查建议用 Biome（单工具同时做 lint + format），或 ESLint + Prettier；先只检查 `src`，避免一次性格式化 Rust/脚本。

### P1-4 macOS Rust 测试被钥匙串挂起

执行 `sh scripts/mac.sh test` 超过 8 分钟没有结束。`sample` 抓到的调用链：

```text
command_tests::diagnostics::detailed_command_...
  -> store.save
    -> secrets::protect
      -> secrets_macos::protect (secrets_macos.rs:69)
        -> key() (secrets_macos.rs:23)
          -> SecItemCopyMatching -> SecurityServer -> mach_msg2_trap
```

同时其他测试线程停在同一文件的互斥锁：

```text
secrets_macos.rs:22
  -> std::sync::Mutex::lock
    -> __psynch_mutexwait
```

根因：所有测试 fixture 只要保存了 `isSecret: true` 的变量，就会走真实的 macOS Keychain；`KEY_LOCK` 是全局静态锁，一次钥匙串调用卡住（等待用户授权、钥匙串未解锁或 headless 无 GUI）会让所有并行测试一起挂起。`#[ignore]` 只保护了 `login_keychain_roundtrip` 一个用例，覆盖不了这些隐式调用。

影响：macOS 本机或 CI 无法可靠运行 Rust 测试；开发者会误以为测试死循环；与 `docs/macOS.md` 中「钥匙串集成测试单独执行」的描述不符。

建议：在 `cfg(test)` 下注入内存密钥后端（固定 32 字节测试密钥），让 `protect/unprotect` 不触碰 Keychain；保留一个显式 `#[ignore]` 的 Keychain 集成测试。这样单元测试可在无 GUI 环境运行，也避免并行测试互相阻塞。

### P2-4 测试时长与超时抖动

- 默认全量：161 秒；关闭 Web Storage 后：190 秒。
- 关闭 Web Storage 时仍有 4 个用例失败，均为 5 秒默认超时；单独运行相关文件 28/28 通过。
- 大用例 `transfer.test.ts` 构造 9996 个 query 项，属于 CPU 密集测试。

影响：在低核数机器或 CI 上随机红；开发者倾向跳过全量测试。

建议：把重用例 `testTimeout` 提到 15000；给 `transfer` 大预算用例单独分组；在 README 给出 `--maxWorkers=2` 的低配机器命令；不要把性能型断言放在默认 5 秒超时里。

### P2-5 无 ErrorBoundary

`src/App.tsx` 直接渲染工作台，没有顶层错误边界。任一组件在渲染期抛错（例如异常 JSON 文档结构、第三方编辑器状态）都会让整个窗口变空白，且没有恢复入口。

建议：增加 `ErrorBoundary`，显示「重新加载 / 复制诊断信息 / 返回仪表盘」；错误信息写入内存日志，不自动上传。

### P2-6 浅色主题对比度不达标

计算值（实色，不透明度按满值）：

| 位置 | 现值 | 背景 | 对比度 |
| --- | --- | --- | --- |
| `--code-comment` | `#718096` | `--response-code-bg` `#f3f6fa` | **3.70:1** |
| `--chrome-muted` | `#7b8c9c` | `--chrome-bg` `#e4ebf0` | **2.87:1** |
| `--chrome-text` | `#617387` | `#e4ebf0` | **4.05:1** |

影响：浅色模式下注释、标题栏辅助文字在低亮度屏幕或强光环境下难读。

建议：采用 [配色配置方案](../design/EnvDock-配色配置方案.md) 中的修正值（`#56626F` / `#525F6D` / `#4F5D6C`），并把对比度检查写成测试。

### P2-7 主题变量重复维护

`src/themes.css` 现有 `dark`、`light`、`graphite` 三块，每块 78 个变量，共 234 行变量声明；共享规则靠 `:root` 兜底。当前数量一致，但没有测试保证变量名集合一致。新增一个变量若只改两块，第三个主题会静默继承错误值。

建议：

1. 增加测试：解析三个主题块，断言变量名集合完全相同。
2. 把共享的 78 个变量名抽成 `tokens.ts` 或 CSS 注释清单，主题块只提供值。
3. 采用设计方案的 `navy / paper / coffee` 三套完整变量。

### P2-8 核心文件过大

- `src-tauri/src/store.rs` 2231 行（已有 `store/` 子模块，但主文件仍含大量命令与迁移逻辑）。
- `src/hooks/useWorkbench.ts` 451 行，返回近 60 个字段；`App.tsx` 19 KB、单组件承载 6 个页面和 6 个对话框状态。
- `themes.css` 727 行、`styles.css` 489 行。

影响：单文件审查成本高；测试只能覆盖整体行为，难以定位回归。

建议：按「工作区保存 / 请求执行 / 导入导出 / 标签与历史」拆分 hook；把 App 的导航、命令面板、弹窗开关拆成 `useAppShell`；Rust 侧把迁移、变量加密、响应缓存继续下沉到 `store/`。

### P2-9 键盘监听重绑

`App.tsx` 的 `useEffect` 依赖 `[model, temporary, isTemporary, page]`，而 `useWorkbench()` 每次渲染返回新的对象字面量。任何工作区状态变化都会解绑并重绑 `window` 的 keydown 监听。

影响：高频输入/流式响应时产生额外监听器增删；闭包捕获旧值的风险随逻辑增长。

建议：把需要的函数与值拆成稳定引用（`useCallback` / ref），或使用 `useEffectEvent`（React 19）只注册一次监听。

### P2-10 启动失败 panic

`src-tauri/src/lib.rs` 使用：

```rust
.expect("WebView2 创建结果已确认失败");
.expect("EnvDock 启动失败：请检查数据目录权限与系统 WebView 运行环境");
```

影响：数据目录不可写、WebView 运行库缺失时，进程直接崩溃；用户只看到系统级崩溃，没有可操作提示。

建议：启动路径返回 `Result`，失败时用原生对话框显示数据目录与修复建议，并保留一个最小诊断日志文件。

### P3 级问题

- **P3-11 CSP 加固**：当前 `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src ipc: http://ipc.localhost`。建议追加 `object-src 'none'; base-uri 'self'; frame-ancestors 'none'; form-action 'none'`。`unsafe-inline` 如被 CodeMirror 依赖，可评估 nonce/hash。
- **P3-12 语言**：NSIS 配置有 `English`，但应用界面全是中文硬编码。要么去掉 English 选项，要么明确标注「安装向导支持英文，应用界面仅中文」。
- **P3-13 脚本**：`npm run desktop` 直接调用 PowerShell；macOS 上应报错或自动切到 `desktop:mac`。建议把原脚本改名 `desktop:windows`，`desktop` 用 Node 包装按平台分派。
- **P3-14 署名**：状态栏 `著作:lxs` 与 LICENSE / publisher 的 `ljy-codes` 不一致。若非同一人，应补充说明；若是笔名，统一为一种。
- **P3-15 打包测试**：13 个包测试全部通过，但只断言 Windows NSIS 模板、权限和卸载逻辑；`tauri.macos.conf.json` 的 `app/dmg`、`icon.icns`、`minimumSystemVersion`、ad-hoc 签名没有断言。建议补 3~5 条 macOS 配置断言。
- **P3-16 文档陈旧**：README 写便携版输出 `publish\EnvDock-1.0.0-portable-preview`，实际脚本按 `package.json` 版本生成。改为 `publish\EnvDock-<version>-portable-preview`。
- **P3-17 仓库卫生**：`src-tauri/target/` 7.0 GB、`backups/` 159 MB、`publish/` 65 MB。均被 `.gitignore` 忽略，但会拖慢备份和磁盘清理。建议加 `scripts/clean.ps1`/`clean.sh`，只保留最近一个 `publish` 与一个 `backups`。
- **P3-18 版本号同步**：`1.8.1` 同时出现在 `package.json`、`package-lock.json`、`Cargo.toml`、`Cargo.lock`、`tauri.conf.json` 和 README，构建脚本只读取 `package.json`。发版时容易漏改 `tauri.conf.json`，导致安装包版本与前端版本不一致。建议加 `scripts/check-version.mjs`，在打包前断言全部一致。

## 已验证的优点

- `npx tsc -b` 通过，严格模式无类型错误。
- `npm audit --omit=dev`：0 个漏洞。
- `npm run test:packaging`：13/13 通过。
- 请求传输显式关闭重定向、系统代理、无效证书与无效主机名（`engine/transport.rs`）。
- 敏感变量走 DPAPI / macOS Keychain + AES-256-GCM；响应缓存也加密，且有大小上限。
- 项目文件读写限制扩展名、10 MiB、普通文件、非符号链接，写入使用同目录临时文件 + fsync + rename。
- 1101 个前端用例覆盖了大量边界；Rust 侧也有存储、引擎和迁移测试，但受 P1-4 影响，本机全量 `cargo test` 未能跑完。
