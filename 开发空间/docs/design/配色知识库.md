## 三条硬规则

1. **对比度**：正文 ≥ 4.5:1；大字、图标、控件、焦点态 ≥ 3:1。
2. **颜色数量**：1 个主色 + 1 个强调色 + 一组中性色；最多再加 2–4 个语义色。
3. **面积比例**：底色 60–70%，文字与主体 20–30%，强调色 5–10%。

> 一句话：**先用明度搭层级，再用色相定气质，最后用彩度做强调。**

## 01 · 色彩基础
配色的第一步不是「选颜色」，而是理解颜色由哪些变量组成、哪些变量决定可读性、哪些变量决定气质。

---

### 1. 四个坐标：色相、明度、彩度、色温

| 维度 | 含义 | 主要作用 | 例子 |
|---|---|---|---|
| 色相 Hue | 颜色在色环上的位置 | 决定气质与联想 | 红、橙、黄、绿、青、蓝、紫 |
| 明度 Lightness / Value | 黑白程度 | 决定层级、可读性、重量 | 深蓝 vs 浅蓝 |
| 彩度 Chroma / Saturation | 鲜艳程度 | 决定强调与情绪强度 | 灰蓝 vs 克莱因蓝 |
| 色温 Temperature | 偏暖或偏冷 | 决定亲近感与距离感 | 橙暖、蓝冷 |

**优先级**：明度 > 彩度 > 色相。

- 明度错，整个界面会糊；
- 彩度错，会显得廉价或刺眼；
- 只有色相错，通常还能通过调整明度与彩度救回来。

---

### 2. 色彩空间：HEX、HSL、OKLCH、CMYK

#### 2.1 常见格式

| 格式 | 用途 | 优点 | 局限 |
|---|---|---|---|
| HEX | Web / UI / 设计交付 | 通用、短 | 不可直接计算明度 |
| RGB | 屏幕显示 | 直观 | 与感知不均匀 |
| HSL | 快速调色 | 易理解 | **感知不均匀**，容易踩坑 |
| Lab / LCH | 色彩计算 | 接近人眼感知 | 工具支持不如 HEX 广 |
| OKLCH | 现代设计系统 | 感知均匀、适合生成色阶 | 需要较新浏览器 / 工具 |
| CMYK | 印刷 | 印刷标准 | 屏幕与印刷存在色差 |
| Display P3 | 广色域屏幕 | 更鲜艳 | 需要色彩管理，Web 需回退 |

#### 2.2 为什么 HSL 不好用

HSL 的 `L=50%` 不等于「看起来一样亮」：

- `hsl(60 100% 50%)` 是刺眼的纯黄；
- `hsl(240 100% 50%)` 是深蓝。

同样的 L 和 S，黄色看起来比蓝色亮得多。用它做色阶，会出现「黄色过曝、蓝色过暗」的问题。

#### 2.3 为什么推荐 OKLCH

OKLCH 把「感知亮度」单独拿出来：

```text
oklch(L C H)
L: 0–1     感知明度
C: 0–0.4   彩度
H: 0–360   色相
```

优点是：

1. 同样的 L，看起来就是差不多亮；
2. 改 H 不会大幅改变明度；
3. 适合生成 10–12 级色阶；
4. 容易做深浅主题映射。

一个实用的品牌色阶（示意）：

| 级别 | L | C | 用途 |
|---|---:|---:|---|
| 50 | 0.97 | 0.02 | 页面底色 |
| 100 | 0.94 | 0.04 | 浅色区块 |
| 200 | 0.89 | 0.07 | 边框 / 分隔 |
| 300 | 0.82 | 0.11 | 禁用态 |
| 400 | 0.73 | 0.15 | 次级强调 |
| 500 | 0.63 | 0.18 | 主色 |
| 600 | 0.54 | 0.19 | Hover |
| 700 | 0.45 | 0.17 | Active |
| 800 | 0.36 | 0.14 | 深色文字 |
| 900 | 0.27 | 0.10 | 标题 |
| 950 | 0.18 | 0.06 | 深底 |

> 彩度不是线性增长：浅色和深色端都要降低 C，否则会「发脏」或「发光」。

---

### 3. 明度是第一顺序

#### 3.1 灰度测试

把配色转成灰度，只看明度：

- 如果层级仍然清楚，配色基本成立；
- 如果灰度下糊成一片，换色也救不回来。

#### 3.2 明度差建议

| 关系 | 明度差（L*） | 例子 |
|---|---:|---|
| 背景 vs 卡片 | 3–6 | #F7F9FC vs #FFFFFF |
| 卡片 vs 浮层 | 4–8 | #FFFFFF vs #F1F5F9 |
| 正文 vs 背景 | ≥ 45 | #16202A vs #F7F9FC |
| 次要文字 vs 背景 | ≥ 30 | #667085 vs #F7F9FC |
| 边框 vs 背景 | 8–15 | #DDE3EA vs #F7F9FC |

> 深色界面不要只用一个黑：背景、侧栏、卡片、浮层至少拉开 4 层。

---

### 4. 对比度：唯一不能妥协的指标

#### 4.1 WCAG 2.2 阈值

| 用途 | 最低对比度 | 等级 | 说明 |
|---|---:|---|---|
| 普通正文 | 4.5:1 | AA | 小于 18pt / 24px 的文字 |
| 大号文字 | 3:1 | AA | ≥ 24px，或 ≥ 18.66px 粗体 |
| UI 组件 / 图形 | 3:1 | AA | 按钮、输入框、图标、焦点态 |
| 增强正文 | 7:1 | AAA | 长文、低视力用户 |
| 装饰元素 | 不要求 | — | 但不能承载唯一信息 |

#### 4.2 对比度公式

```text
(L1 + 0.05) / (L2 + 0.05)
```

其中 L 是相对亮度：

```text
L = 0.2126 R + 0.7152 G + 0.0722 B
R/G/B 需先做 sRGB 线性化
```

#### 4.3 APCA（补充参考）

APCA 更贴近阅读体验，但尚未进入 WCAG 2.2：

| 用途 | 建议 Lc |
|---|---:|
| 小字正文 | 90+ |
| 正文 | 75+ |
| 大号文字 | 60+ |
| 标题 | 45+ |
| 非文本 / 图标 | 30+ |

> 合规仍以 WCAG 为准；APCA 用来判断「读起来累不累」。

#### 4.4 常见误区

- 白底灰字 `#999` 只有约 2.8:1，不能做正文；
- 蓝底白字不一定够，`#2F6BFF` 上的白字约 4.6:1，刚好过 AA；
- 黄色底黑字通常很好，但黄底白字几乎不可读；
- 半透明文字要按最终混合后的颜色计算。

### 5. 六种色彩和谐关系

| 关系 | 色相角 | 气质 | 适合 |
|---|---|---|---|
| 单色 | 0° | 统一、克制 | 工具、B 端、极简 |
| 邻近 | 30–60° | 柔和、自然 | 生活、教育、插画 |
| 互补 | 180° | 强对比、戏剧性 | 活动、促销、海报 |
| 分裂互补 | 150–210° | 有对比但不刺眼 | 品牌、封面 |
| 三角 | 120° | 活泼、丰富 | 插画、儿童、创意 |
| 四方 | 两组互补 | 复杂、热闹 | 大型活动（慎用） |

#### 5.1 60-30-10 面积法

- **60%**：背景 / 大面积中性色
- **30%**：文字 / 主体 / 次要色
- **10%**：强调色 / CTA / 点缀

> 高饱和色永远小面积；低饱和色可以大面积。

#### 5.2 例子：墨蓝专业

```text
背景 #F7F9FC 60%
文字 #16202A 30%
主色 #2F6BFF 8%
辅色 #12A594 2%
```

### 6. 彩度与「高级感」

「高级感」通常来自：

1. 低饱和的大面积；
2. 少量高饱和的点缀；
3. 明度层级清楚；
4. 中性色带一点色相（暖灰 / 冷灰），而不是纯灰。

对比：

| 做法 | 结果 |
|---|---|
| 大面积纯黑 + 纯白 + 荧光色 | 廉价、刺眼 |
| 大面积暖灰 + 深墨字 + 一个低饱和橙 | 克制、有质感 |
| 大面积克莱因蓝 + 白 | 强品牌、视觉冲击 |
| 大面积莫兰迪 + 一点金属色 | 柔和、精致 |

### 7. 色彩心理与行业语义

| 颜色 | 常见联想 | 适合 | 风险 |
|---|---|---|---|
| 蓝 | 信任、专业、科技、冷静 | 金融、SaaS、工具、医疗 | 过于常见、缺乏个性 |
| 绿 | 增长、健康、自然、安全 | 健康、环保、金融、效率 | 金融里也可能表示下跌（西方） |
| 红 | 热情、警示、促销、危险 | 活动、餐饮、媒体、错误 | 大面积易焦虑 |
| 橙 | 活力、亲切、创造 | 生活、教育、社交 | 容易显得廉价 |
| 黄 | 阳光、注意、乐观 | 促销、儿童、警告 | 白字不可读 |
| 紫 | 创意、神秘、尊贵 | AI、美妆、艺术 | 容易过度设计 |
| 粉 | 温柔、女性、浪漫 | 美妆、社交、生活 | 容易刻板 |
| 黑 | 高端、权威、极简 | 品牌、时尚、工具 | 大面积压抑 |
| 白 | 干净、留白、医疗 | 极简、阅读、医疗 | 缺少层次 |
| 金 | 奢华、传统、尊贵 | 金融、礼盒、国风 | 容易俗气 |
| 灰 | 中性、克制、背景 | 所有界面 | 纯灰会显得冷淡 |

> 颜色没有固定含义，**行业 + 文化 + 使用面积**共同决定语义。

### 9. 色盲与可访问性

#### 9.1 三类常见色盲

| 类型 | 影响 | 占比（男性） |
|---|---|---:|
| 红色盲 Protanopia | 红、绿、棕难分 | 约 1% |
| 绿色盲 Deuteranopia | 红、绿难分 | 约 5% |
| 蓝黄色盲 Tritanopia | 蓝、绿、黄难分 | 约 0.01% |

#### 9.2 设计对策

1. **不要只靠颜色传达状态**：加图标、文字、形状、位置。
2. **红绿不要做唯一区分**：用蓝橙、紫黄替代。
3. **图表用色盲安全色板**：Okabe-Ito、Viridis、Cividis。
4. **检查灰度**：状态在灰度下仍能区分。
5. **避免低对比的浅色文字**。

#### 9.3 Okabe-Ito 8 色

```text
#E69F00  #56B4E9  #009E73  #F0E442
#0072B2  #D55E00  #CC79A7  #000000
```

### 10. 屏幕与印刷

| 项目 | 屏幕 | 印刷 |
|---|---|---|
| 色彩模型 | RGB / sRGB / P3 | CMYK |
| 黑色 | 可用 #000 | 用四色黑或专黑，避免大面积单黑 |
| 亮色 | 屏幕更亮 | 纸面更暗 |
| 色域 | P3 更广 | CMYK 更窄 |
| 交付 | HEX / RGB | CMYK + 专色 + 打样 |

#### 10.1 实用建议

- 屏幕设计用 `#000` 可以，但 UI 大背景更推荐 `#0B0C0F` 这类近黑；
- 印刷前把高饱和荧光色降 10–20%；
- 金色、银色在屏幕上用渐变模拟，印刷要用专色；
- 重要品牌色必须打样，不能只看屏幕。

### 11. 常见错误 20 条

1. 只用 HSL 调色阶，导致黄亮蓝暗。
2. 深色界面只用一种黑。
3. 正文对比度低于 4.5:1。
4. 只用颜色表示成功 / 失败。
5. 一套界面出现 5 个以上主色相。
6. 强调色占大面积。
7. 纯灰中性色，缺少温度。
8. 白底用纯黑字，阅读疲劳。
9. 深底用纯白字，刺眼。
10. 渐变色相跨度过大，像彩虹。
11. 图标颜色超过 3 个。
12. 图标里放文字。
13. 封面标题压在复杂图片上，没有蒙版。
14. 图表用彩虹色表示顺序数据。
15. 分类色板超过 8 色。
16. 红绿色盲无法区分涨跌。
17. 品牌色直接当危险色。
18. 浅色模式与深色模式只做反色，不重新调层级。
19. 色值与实际渲染不一致（半透明、混合模式）。
20. 没有在真实设备 / 小尺寸上验证。

## 02 · 配色方法论
这一篇给的是「可执行的配方」。每个方法都包含：什么时候用、怎么做、坑在哪。

---

### 0. 标准流程

```text
明确目的 → 选主色 / 灵感 → 建中性色阶 → 定语义色 → 分配面积 → 验证 → 交付 token
```

#### 0.1 先回答 6 个问题

1. 这是工具、图标、封面还是数据图？
2. 主要受众是谁？（专业 / 大众 / 年轻 / 企业）
3. 需要什么气质？（信任 / 活力 / 高级 / 温柔 / 科技）
4. 主色是否已被品牌规定？
5. 有没有必须保留的颜色？（产品色、肤色、照片色）
6. 最终在什么设备、什么尺寸、什么光线下看？

#### 0.2 时间分配建议

| 阶段 | 时间占比 | 产出 |
|---|---:|---|
| 明确目的 | 10% | 关键词、参考图 |
| 选主色 | 15% | 1 个主色 + 2 个备选 |
| 建色阶 | 25% | 10–12 级中性色 + 品牌色阶 |
| 分配角色 | 20% | 背景/文字/强调/语义 |
| 验证 | 20% | 对比度、灰度、色盲、小尺寸 |
| 交付 | 10% | token / 色板 / 说明 |

---

### 方法 A：单色阶（最稳）

**适合**：软件工具、B 端、极简品牌、图标底色。

**做法**：

1. 选一个品牌色相 H；
2. 用 OKLCH 生成 10–12 级：
   - L 从 0.97 到 0.18；
   - C 在中间最高，两端降低；
3. 背景用 50/100，边框用 200/300，主色用 500/600，文字用 800/900。

**示例：蓝色阶**

```text
#EFF6FF #DBEAFE #BFDBFE #93C5FD #60A5FA
#3B82F6 #2563EB #1D4ED8 #1E40AF #1E3A8A #172554
```

**坑**：

- 只有明度变化会显得单调 → 加一个低饱和辅助色；
- 纯蓝容易「企业模板感」→ 加一点青或紫做偏移。

---

### 方法 B：中性色 + 一个强调色（最实用）

**适合**：90% 的软件工具、后台、文档、开发者工具。

**比例**：

```text
中性色 90%（背景、卡片、边框、文字）
强调色 10%（按钮、链接、选中态、关键数据）
```

**做法**：

1. 建一套带色相的中性色（暖灰 / 冷灰 / 蓝灰）；
2. 只选一个高饱和强调色；
3. 语义色（成功/警告/危险）各一个，不参与品牌表达。

**示例：暖灰 + 橙**

```text
背景 #F7F3EE
卡片 #FFFDF9
边框 #E4D9CC
次要 #7A6A5C
文字 #2B2118
强调 #C2410C
```

**坑**：

- 强调色用太多 → 失去重点；
- 中性色太冷 → 工具感过强；
- 语义色和强调色太接近 → 用户分不清。

---

### 方法 C：60-30-10

**适合**：封面、海报、品牌页、演示文稿。

| 比例 | 角色 | 颜色类型 |
|---:|---|---|
| 60% | 背景 / 大面积 | 低饱和中性色或深色 |
| 30% | 主体 / 文字 | 高对比中性色 |
| 10% | 强调 / 点缀 | 高饱和色 |

**例子：深底大字封面**

```text
60% #0E0E10
30% #F5F1E8
10% #E4572E
```

**坑**：

- 10% 不是「至少 10%」，而是「不超过 10%」；
- 大面积高饱和会视觉疲劳；
- 文字本身也算 30% 的一部分。

---

### 方法 D：互补撞色

**适合**：活动、促销、海报、需要强记忆点的封面。

**做法**：

1. 选主色 H；
2. 取 H + 180°；
3. 一方降饱和做大面积，一方高饱和做小面积；
4. 用中性色隔开。

**例子：藏青 × 赤金**

```text
#2E4E7E  #F2BE45
```

**坑**：

- 两边都高饱和会刺眼；
- 互补色交界处容易「振动」；
- 红绿互补对色盲不友好。

---

### 方法 E：分裂互补

**适合**：想要对比但不想太刺激的品牌、封面、插画。

**做法**：主色 H，搭配 H+150° 与 H+210°。

**例子**：蓝 + 橙红 + 黄绿。

**优点**：比正互补更耐看，层次更丰富。

---

### 方法 F：三角配色

**适合**：插画、儿童、创意活动、需要活泼感的产品。

**做法**：色相环 120° 三点。

**例子**：`#4F46E5` `#F59E0B` `#10B981`

**坑**：

- 三色都高饱和 → 像玩具；
- 必须有一个主色占主导，另外两个做辅助。

---

### 方法 G：邻近色

**适合**：自然、生活、教育、柔和品牌。

**做法**：H、H+30°、H+60°。

**例子**：蓝绿 → 青 → 蓝。

**优点**：统一、舒服、容易做出层次。

**坑**：缺少对比，需要靠明度拉开。

---

### 方法 H：同明度不同色相（莫兰迪）

**适合**：高级感、女性、生活方式、家居、服装。

**做法**：

1. 固定 L 在 0.55–0.75；
2. C 控制在 0.03–0.10；
3. 只变化 H。

**例子**：

```text
#E8E2DC  #D8C3B4  #B7C4C7  #A68A7B  #4A4441
```

**优点**：柔和、耐看、容易搭配。

**坑**：对比不足，文字必须单独加深。

---

### 方法 I：低饱和底 + 高饱和点

**适合**：封面、品牌、活动、需要「高级但有精神」的画面。

**公式**：

```text
背景：L 0.85–0.95，C 0.02–0.06
主体：L 0.25–0.45，C 0.02–0.08
强调：L 0.55–0.65，C 0.18–0.28
```

**例子**：米白 + 墨 + 朱红。

---

### 方法 J：从图片取色

**适合**：封面、品牌、图标、需要和照片统一的界面。

#### 流程

1. 选一张主图；
2. 用 MMCQ / k-means 提取 6–8 个主色；
3. 按明度和饱和度分配到角色：
   - 最亮的低饱和色 → 背景；
   - 最暗的色 → 文字；
   - 最饱和的色 → 强调；
   - 中间色 → 卡片 / 边框；
4. 人工微调，保证对比度；
5. 检查肤色、产品色是否被改变。

#### 伪代码

```python
from colorthief import ColorThief

palette = ColorThief("cover.jpg").get_palette(color_count=8, quality=10)
# 按亮度排序
palette.sort(key=lambda c: 0.2126*c[0] + 0.7152*c[1] + 0.0722*c[2])
bg      = palette[-1]   # 最亮
text    = palette[0]    # 最暗
accent  = max(palette, key=lambda c: max(c) - min(c))  # 最饱和
```

#### 坑

- 自动取色经常得到脏色 → 必须人工筛；
- 图片压缩会产生偏色；
- 人物肤色不能直接用算法改；
- 背景色太亮时文字要加深。

---

### 方法 K：传统色 / 名画取色

**适合**：国风、文化、品牌故事、封面、包装。

**做法**：

1. 选一个历史色板（中国传统色、Sanzo Wada、日本传统色）；
2. 只取 3–5 色，不要整组照搬；
3. 用其中一个做底，一个做文字，一个做强调；
4. 用现代中性色做过渡。

**例子**：胭脂 × 月白 × 赤金。

**坑**：

- 传统色名称很美，但屏幕色值不一定准确；
- 古画颜色偏暗，直接用于 UI 会太闷；
- 文化符号不要混用。

---

### 方法 L：系列化配色

**适合**：多张封面、多个图标、一组表情包、系列海报。

#### 两种策略

| 策略 | 固定 | 变化 | 效果 |
|---|---|---|---|
| A | 底色 | 点缀色 | 统一、适合系列 |
| B | 点缀色 | 底色 | 有节奏、适合多主题 |

**规则**：

- 同一系列最多 1 个变量；
- 字体、构图、圆角、阴影保持一致；
- 每张只换一个颜色角色；
- 建立「系列色板」并记录。

---

### 3. 生成 12 级色阶的公式

```text
step   L      C 系数
50     0.97   0.25
100    0.94   0.35
200    0.89   0.50
300    0.82   0.65
400    0.73   0.80
500    0.63   1.00
600    0.54   1.00
700    0.45   0.90
800    0.36   0.75
900    0.27   0.55
950    0.18   0.35
```

实际 C = 基准 C × 系数。基准 C 建议：

| 色相 | 基准 C |
|---|---:|
| 红 | 0.20 |
| 橙 | 0.18 |
| 黄 | 0.15 |
| 绿 | 0.16 |
| 青 | 0.14 |
| 蓝 | 0.18 |
| 紫 | 0.20 |
| 粉 | 0.18 |

> 黄色天生彩度高，基准 C 要低；紫色可以高一些。

2. 背景、卡片、文字三层清楚吗？

### 6. 常见失败模式

| 症状 | 原因 | 修复 |
|---|---|---|
| 页面「脏」 | 中性色带错色相 / 彩度太高 | 降 C、统一色相 |
| 页面「灰」 | 明度差不足 | 拉开背景/卡片/文字 |
| 页面「花」 | 主色相太多 | 砍到 1–2 个 |
| 页面「廉价」 | 高饱和大面积 | 降饱和、缩小强调面积 |
| 页面「闷」 | 深色太黑、文字太灰 | 提亮背景、增加层次 |
| 页面「刺眼」 | 纯白 + 纯黑 + 荧光 | 用近白近黑 |
| 文字「糊」 | 对比不足 / 字重太细 | 提高对比、加粗 |
| 图表「乱」 | 分类色太多 | ≤ 6 色、用色盲安全板 |

#### 深色界面 8 条

1. 不要纯黑 `#000`；用 `#0B0F14`–`#12161C`。
2. 背景、侧栏、卡片、浮层至少 4 层。
3. 主文字不要纯白；用 `#E6EDF7` 这类近白。
4. 高饱和色只给 CTA、状态、关键数据。
5. 阴影在深色里效果弱，用边框和明度差做层级。
6. 图表网格线降到 10–15% 透明度。
7. 图片和视频要加暗色蒙版，避免刺眼。
8. 深色模式不是反色：重新分配层级与语义。

### 9. 数据密集界面

- **表头**：比正文低一档明度，不要用重色块。

- **图表**：放在卡片内，网格线弱化，主色 1–3 个。

## 04 · 软件图标配色
图标不是缩小版海报。它要在 **16px** 下仍然可辨认，在 **1 秒** 内传达产品类别，在**不同背景**上都成立。

---

### 1. 三个目标

1. **识别**：小尺寸下轮廓清楚。
2. **记忆**：颜色与形状形成固定组合。
3. **一致**：同一产品线的图标像一家人。

---

### 2. 颜色数量

| 类型 | 颜色数 | 结构 |
|---|---:|---|
| 单色图标 | 1 | 1 个前景色 + 透明 |
| 双色图标 | 2 | 主色 + 反白 / 深色 |
| App Icon | 2–3 | 底 / 主体 / 高光 |
| 拟物图标 | 3–5 | 但必须有主色 |

> 超过 3 个色相的 App Icon，90% 会显得乱。

---

### 3. 明度结构 60-30-10

| 部分 | 占比 | 例子 |
|---|---:|---|
| 底色 / 背景 | 60–70% | 深蓝 `#0B1F3A` |
| 主体 / 图形 | 25–35% | 亮蓝 `#2F6BFF` |
| 高光 / 点缀 | 5–10% | 白 `#FFFFFF` |

---

### 4. 渐变规则

1. **同色相或邻近色相**：蓝 → 青、紫 → 粉。
2. **2–3 个停靠点**：不要 5 个以上。
3. **角度 135°**：左上到右下最自然。
4. **明度差 15–25%**：太小看不出，太大像两块色。
5. **不要彩虹渐变**：除非品牌本身就是多彩。

示例：

```css
background: linear-gradient(135deg, #7C3AED 0%, #22D3EE 100%);
```

### 5. 平台规范

| 平台 | 画布 | 形状 | 注意 |
|---|---|---|---|
| macOS | 1024×1024 | 圆角矩形（squircle） | 常用内容区约 824×824，四周约 100px 留白；以 Apple 模板为准 |
| iOS | 1024×1024 | 系统自动裁圆角 | 不要预裁圆角、不要透明 |
| Android | 108×108 dp | 自适应图标 | 前景 / 背景两层，72×72 dp 安全区 |
| Windows | 256×256 | 系统不强制圆角 | 同时导出 16/24/32/48/64/128 |
| Web favicon | 16/32/48 | 方形 | 小尺寸要简化 |
| PWA | 192/512 | 方形 / maskable | 留 10% 安全边 |

#### 导出尺寸

```text
1024, 512, 256, 128, 64, 48, 32, 16
```

- 1 个颜色；

- 不用于 App Icon 主图。

#### 9.2 双色面性

- 主色 + 8–15% 透明度的同色；
- 适合功能入口、空状态；
- 轮廓要闭合。

#### 9.3 渐变 App Icon

- 2–3 色渐变；
- 中心放一个简单几何标记；
- 加一层顶部高光；
- 适合 AI、创作、媒体。

#### 9.4 拟物 / 3D

- 3–5 色，但主色占 70%；
- 光影方向统一；
- 小尺寸要降细节；
- 适合游戏、工具、品牌。

### 10. 小尺寸测试

1. 把图标缩到 **16px / 32px**；
2. 离屏幕 1 米看，能否辨认；
3. 转灰度，轮廓是否还清楚；
4. 放到浅色和深色背景上各看一次；
5. 和同产品线其他图标并排，是否像一家人。

#### 快速判断

| 问题 | 修复 |
|---|---|
| 16px 糊成一团 | 减少细节、加大主体 |
| 32px 看不出类别 | 换更具体的符号 |
| 深色背景消失 | 加描边或反白 |
| 浅色背景太淡 | 加深主体 |
| 和别的图标不像 | 统一圆角、线宽、色温 |

### 11. 制作流程

```text
1. 定类别与气质
2. 选一套 2–3 色
3. 画 1024×1024 矢量
4. 主体控制在 60–70% 画布
5. 加 squircle 圆角（macOS）或满幅（iOS）
6. 加 1 层高光 / 轻阴影
7. 导出 1024 PNG
8. 生成 512/256/128/64/48/32/16
9. 在真实 Dock / 桌面 / 启动器预览
10. 记录色值与版本
```

#### macOS 圆角参考

```text
画布 1024×1024
内容区约 824×824
四周留白约 100px
圆角半径约 185px
```

> 具体以 Apple 官方图标模板为准；不同系统版本略有差异。

---

### 12. 常见错误

1. 图标里放文字（16px 必糊）。
2. 颜色超过 3 个色相。
3. 纯黑 + 纯白 + 荧光色。
4. 渐变跨度太大，像彩虹。
5. 细线在 16px 消失。
6. 主体太小，四周留白太多。
7. 深色图标放深色背景，没有描边。
8. 每个图标圆角、线宽不一致。
9. 直接拿照片当图标。
10. 没有导出多尺寸。

### 4. 标题可读性

| 元素 | 建议 |
|---|---|
| 大标题 | ≥ 3:1，最好 4.5:1 |
| 小字 | ≥ 4.5:1 |
| 字重 | 700–900 |
| 字距 | 标题 -0.02em 到 -0.04em |
| 行高 | 0.95–1.1 |
| 每行字数 | 中文 6–10 字 |
| 最多行数 | 2–3 行 |

#### 文字压图的 8 种解法

1. 黑色 40–60% 蒙版。
2. 从下到上的渐变蒙版。
3. 文字后面加纯色块。
4. 文字加同色系描边。
5. 图片局部模糊。
6. 文字放在图片留白区。
7. 文字加深色底条。
8. 换一张更适合的图。

> 阴影是最弱的解法；能加蒙版就不要只加阴影。

### 5. 从图片取色

#### 映射规则

| 图片颜色 | 角色 |
|---|---|
| 最亮、低饱和 | 背景 |
| 最暗 | 标题 / 正文 |
| 最饱和 | 点缀 / 按钮 |
| 中间色 | 卡片 / 分隔 |
| 肤色 | 保留，不参与配色 |

#### 步骤

1. 选主体明确的图；
2. 提取 6–8 色；
3. 按亮度排序；
4. 选 1 个背景、1 个文字、1 个点缀；
5. 检查标题对比度；
6. 保留产品色与肤色。

## 06 · 数据可视化配色
图表配色的目标不是好看，而是**让差异可比较、让顺序可理解、让重点被看见**。

---

### 1. 三类色板，先选对类型

| 类型 | 用途 | 颜色关系 | 例子 |
|---|---|---|---|
| 分类 Categorical | 不同类别、无顺序 | 色相差异大 | 渠道、地区、产品线 |
| 顺序 Sequential | 从低到高 | 单色相 / 双色相渐变 | 销售额、温度、密度 |
| 发散 Diverging | 有中点、正负 | 两端对比 + 中性中点 | 增长率、盈亏、偏差 |

> 最常见的错误：用彩虹色表示顺序数据，或用同一色相表示无序类别。

---

### 2. 分类色板

#### 2.1 规则

- 最多 **6–8 色**；
- 相邻颜色明度差 ≥ 15；
- 红绿不要相邻；
- 重要类别用高饱和 / 深色，其他类别降饱和；
- 超过 8 类 → 合并为「其他」或用小多图。

5. **金色只做小面积**：文字、线、印章。
6. **传统色 + 现代中性色**：避免过于古旧。

### 2. Sanzo Wada 348 组

《A Dictionary of Color Combinations》（配色总鉴）收录了日本昭和初期画家和田三造整理的配色方案。它的特点是：

- 2–4 色一组；
- 颜色偏灰、偏暗，适合印刷与织物；
- 组合关系经过历史筛选，拿来即用；
- 适合封面、插画、品牌、包装、图标。

#### 2.1 使用建议

1. 先看组合的**明度关系**，再决定谁是底、谁是字、谁是点。
2. 2 色组合适合双色海报 / 图标；3–4 色适合封面 / 插画。
3. 直接用于屏幕时，适当提高明度与对比度。
4. 不要整组照搬 20 色，选 3–5 色即可。
5. 记录组合编号，方便复用与引用。

### 4. 传统色现代化的 6 个方法

1. **降饱和**：古色直接上屏会偏暗，降 10–20% 彩度。
2. **提明度**：深色做底，浅色做文字。
3. **加中性色**：用月白、霜色、墨色做过渡。
4. **控制面积**：传统色做点缀，现代中性色做底。
5. **统一材质**：纸纹、墨迹、印章只选一种。
6. **少即是多**：一套画面 3–5 色足够。

### 8. 许可与使用边界

| 类型 | 通常许可 | 能否商用 | 注意 |
|---|---|---|---|
| 代码库 | MIT / Apache-2.0 | 可以 | 保留版权声明 |

| 传统色名称 | 公共文化 | 可以 | 色值需自行复核 |

> 最稳妥的做法：**代码按 LICENSE，颜色值自己重新取样，品牌名只做说明性引用。**

### 1. 三条硬规则

```text
1. 正文 ≥ 4.5:1；大字 / 控件 ≥ 3:1
2. 1 主色 + 1 强调 + 一组中性色；语义色最多 4 个
3. 底 60–70% / 主体 20–30% / 强调 5–10%
```

| 用途 | 最低 | 等级 |
|---|---:|---|

| UI 组件 / 图标 | 3:1 | AA |
| 增强正文 | 7:1 | AAA |
| 装饰 | 不要求 | — |

### 12. 常见问题 → 修复

| 问题 | 修复 |
|---|---|
| 页面脏 | 降彩度、统一色相 |
| 页面灰 | 拉开明度差 |
| 页面花 | 主色相砍到 1–2 个 |
| 页面廉价 | 降饱和、缩小强调面积 |
| 页面刺眼 | 近黑近白替代纯黑纯白 |
| 文字糊 | 提高对比、加粗 |
| 图标 16px 糊 | 减细节、加主体 |
| 封面标题不清 | 加蒙版 / 色块 |
| 图表乱 | ≤ 6 色、色盲安全板 |
| 深色模式怪 | 重新分配层级，不要反色 |

### 10.8 配色方法摘要

#### 10.8.1 深色 B 端界面 6 点

1. **背景不要只用一种黑**：主背景、侧栏、卡片、浮层拉开 2–4 个明度层级。
2. **高亮色要克制**：高饱和色只留给 CTA、核心数据、状态和趋势。
3. **数据是视觉主角**：金额、增长率、核心指标放大；说明文字与辅助信息后退。
4. **卡片感来自层级**：统一间距、内边距、标题结构和信息节奏，再谈圆角、描边、阴影。
5. **图表融入界面**：弱化网格、坐标、辅助线，图表主色控制在 1–3 个。
6. **科技感不等于发光**：渐变、微光、玻璃质感只做氛围，核心操作区保持清晰。

#### 10.8.2 浅色 B 端工作台 4 层信息

1. **核心业务数据**：KPI、余额、订单、用户数。
2. **趋势分析**：折线图、柱状图。
3. **明细列表**：表格、任务、消息。
4. **辅助信息**：快捷操作、通知、个人中心。

布局记忆点：
- 卡片之间留足呼吸感；统一使用 8 / 16 / 24 的间距体系。
- 圆角保持一致，阴影尽量轻，用留白代替复杂分割线。
- Dashboard 主色不超过 3 个：一个导航/重点色、一个增长/数据色、一个中性背景色。
- 图表按目的选择：折线看趋势、柱状看对比、环形看占比、表格看明细。
