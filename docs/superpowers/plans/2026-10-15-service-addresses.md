# 服务地址统一维护实施计划

**目标：** 当前 1.0.0 继续由环境矩阵维护服务基础地址，移除没有模板引用的重复环境变量，保护已有接口引用与用户草稿。

**调用链：** `EnvironmentMatrix` 更新 `workspace.bindings[].baseUrl`，`useWorkbench` 按原保存流程持久化；Rust `engine/prepare.rs` 将绑定地址交给 `url_builder.rs`。变量通过 `{{名称}}` 在路径、参数、Headers、正文与鉴权中使用。Postman/Yaak 导入的 `Builder` 当前同时保留域名变量和解析出的绑定。

**方案：**

- 新增纯函数识别同项目、同环境、同基础地址的非秘密环境变量；支持截图中不带协议的 IP/端口与明确 HTTP 地址匹配，拒绝凭据、模板、Query、fragment 和无效地址。
- 遍历同项目全部请求、环境独立配置、服务配置和其他变量，保护任何已有模板引用。JSON 正文同时检查解析后的值，避免 Unicode 转义导致漏判；保留秘密变量、不同环境、不同项目与存在重复名称的异常数据。
- 仅移除已匹配且未被引用的变量；不修改绑定、请求或其他变量。没有变化时返回原对象。加载旧工作区只形成未保存草稿，后续沿用现有保存事务；导入转换和合并时复用相同规则。
- 变量页环境作用域提供「配置服务地址」入口，说明基础地址的唯一维护位置；已引用的历史地址变量保留并说明兼容原因。现有变量编辑在失焦时合并未引用的同地址条目，避免每个按键触发清理。
- 环境矩阵修改地址时先依据旧配置清理无引用重复值，防止修改后留下旧地址副本。保持启用、移除绑定和环境隔离语义。
- 不修改版本、数据库结构、Rust 请求引擎、IPC 或真实本机工作区；保留已完成的仪表盘和树/标签快捷功能。

## 风险与验证边界

- 被引用的历史变量继续保持原值，不冒然替换为其他地址或改变其业务语义；需在界面明确说明。
- 加载时产生合并草稿，实际持久化仍需原保存流程成功；保存失败时保留草稿，数据库不被部分更新。
- 不通过读取真实数据库、探测配置中的服务或发送业务请求进行验证。
