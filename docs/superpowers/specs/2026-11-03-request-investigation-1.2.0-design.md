# EnvDock 1.2.0 请求排查扩展

用户已批准前一轮推荐的请求时间线、网络诊断、问题排查包，并明确继续使用 1.2.0。本次沿用当前开发目录，保留未提交的 JSON 工具和云同步试验；不提交、推送、安装或替换旧交付物。

## 范围与取舍

增加一条完整排查流程：发送 → 查看此次诊断 → 时间线查看旧记录 → 两次响应对比／恢复草稿 → 预览脱敏排查包并下载 HTML。

先采用会话历史，最多 50 条、16 MiB 序列化 UTF-8 数据，超限从最旧条目淘汰；单条超限则跳过并提示。关闭应用后清空，清理缓存同时清空会话历史。相比新增数据库历史表，此方案无需迁移和解密边界变化，也避免后台持续落盘；跨重启历史不在本次范围。JSON 工具维持关闭窗口即清空。

## 时间线

完整捕获实际提交的请求模板和临时变量，而非之后编辑的内容；不复制其他环境的配置。保存开始/结束时间、项目/服务/环境名称、脱敏解析地址、响应或错误、原生诊断。只记录实际提交的网络调用，预览、复制 cURL、取消生产确认不记入。结果以 executionId 绑定，切换上下文和并发不串线。

独立懒加载窗口按当前项目展示，可搜索、按环境和成功/错误筛选、删除与清空。选择两条有效、未截断 JSON 响应进行现有差异组件对比。恢复操作明确为“恢复为草稿”：只恢复仍存在的同项目、同服务接口及原环境，保留当前未保存草稿的自动保存语义，不恢复临时变量或历史凭据、不发送请求；multipart 文件项清空并禁用。切换环境及恢复后继续通过现有发送确认流程。

## 网络诊断

新增向后兼容的详细发送命令，原命令保留。成功响应可选携带 diagnostics，旧缓存缺少此字段仍能读。失败结果返回固定类别及安全文本，不透传包含真实 URL 的底层错误链。记录总体耗时、准备耗时、收到响应头前耗时、正文接收耗时；可取得时附 HTTP 版本、远端地址、已接收字节。响应头等待包括连接/TLS/上传，不称作独立 DNS/TCP/TLS/TTFB。取消与整体超时覆盖整个发送链路；不增加重试、重定向、代理或证书跳过。

## 排查包

从不可变历史记录生成独立 HTML，无外部资源与脚本；所有动态内容 HTML 转义，设置限制性 CSP。用户可填写现象与复现步骤，勾选是否包含请求正文、响应正文和响应 Headers，默认不含这三类。JSON 正文按敏感字段名递归脱敏，URL 查询参数、凭据 Header、Cookie、鉴权、模板变量和文件路径隐藏；不能安全处理的非 JSON 正文省略。仅输出当前选中记录，不导出工作区变量或凭据表。请求以模板表示，cURL 使用脱敏模板，不伪装为精确网络抓包；需用户自行补齐地址/凭据。先显示与最终导出一致的预览，再点击下载。导出不自动上传。

## 兼容与验证

保持 npm/Cargo/Tauri 版本 1.2.0、应用标识、数据库 schema 和数据目录；无新运行依赖。新增诊断字段通过 serde default 兼容旧缓存，旧 API 保留。

验证会话容量/淘汰、快照隔离、恢复草稿、生产与并发边界、清理后晚到结果、错误与取消诊断、截断响应、敏感字段/HTML 注入/精确数字、真实组件操作及原生回环 HTTP。执行完整前端/Rust/打包检查与生产构建，并记录结果。
