# 1.4.0 临时请求

用户已确认需要无环境的临时接口，并要求“数据不记录”“版本升级”。

最新澄清：用户允许记录数据，不要求额外无痕机制。核心目标为“有临时可用的方法，避免无环境了无法使用”。以下内存生命周期作为自然实现保留，不扩大为日志擦除或系统级不留痕承诺。

- 提供独立「临时请求」入口；输入完整 HTTP/HTTPS URL，不依赖项目、服务或环境。
- 支持多个内存标签，复用 Params、Headers、鉴权、Body、响应搜索和折叠。
- 凭据直接在当前临时请求填写，不继承工作区变量、服务 Header 或鉴权。
- URL、请求、凭据和响应仅在进程内存中；关闭标签删除，关闭全部清空，重启不恢复。
- 专用 IPC 不读取或写入 Store，不保存响应缓存、不追加时间线、不自动保存，不使用浏览器存储。
- 保留取消、整体超时、响应大小限制、禁止跳转和原生 HTTP 校验。
- 普通已保存接口的归属校验、环境配置、自动保存与缓存保持原有行为。
- Ctrl/Cmd+Enter 按当前页面发送；临时页面的 Ctrl/Cmd+S 不写工作区。
- 使用现有主题与分屏布局；状态明确显示「无环境 · 仅内存」。
- 升级 1.3.0 → 1.4.0，生成 Windows x64 安装包及交付 ZIP；不自动安装或发布。
