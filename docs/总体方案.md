# 本地接口测试工具设计方案（整合版）

编写日期：2026-09-24
项目位置：`D:\专用工具\接口工具`
文档状态：三方案整合基线，尚未进入编码阶段
整合来源：原 `方案.md`、`c-设计.md`、`dp-方案.md`
产品名称：暂定“接口工具”；内部标识暂定 `ApiWorkbench`

## 1. 方案结论

开发一个类似 Postman、Yaak 使用方式的纯本地桌面接口测试工具，Windows 优先，不需要账号、云端存储或独立服务端。

核心业务模型：

> 项目管理服务，服务管理接口；项目配置多个环境，每个服务分别配置各环境下的地址与鉴权。接口定义共用，切换环境时切换运行配置，不复制接口。

拟采用技术栈：

- 桌面框架：Tauri 2。
- 界面：React + TypeScript。
- 本地请求与应用逻辑：Rust。
- 结构化存储：SQLite。
- 大响应、备份与日志：本地文件。

上述选型是本项目建议，不代表已经完成依赖安装或技术验证。具体依赖版本、Windows 支持范围及运行时打包方式，在工程初始化时验证并锁定。

### 1.1 三方案整合原则

本文作为后续设计和实施的统一入口；另外两份提案保留原文用于追溯，其中冲突内容不再作为并行实施要求。整合不是将三份文本直接拼接，也不意味着已经实现其中的功能。

| 维度 | 整合决定 | 来源与取舍 |
|---|---|---|
| 领域模型 | 项目 → 服务 → 目录/接口，环境为独立运行配置维度 | 延续原方案与 dp；c 正文也明确服务与接口定义不随环境变化，统一消除其树形示意歧义 |
| 持久化 | SQLite 是唯一运行时配置数据源，文件负责响应、备份和交换 | 采用原方案与 dp；不同时维护 JSON 与数据库两份可编辑主数据 |
| 可读性与 Git | 交换文件内部使用 JSON；后续可提供脱敏、稳定排序的目录导出 | 吸收 c 的可读文件思路，但不把 Git 同步或外部文件实时编辑列入首版 |
| 技术栈 | Tauri 2 + React + TypeScript + Rust | 不同时保留 Vue、Electron、JavaFX 三条实现路线；不照搬提案中的历史依赖版本 |
| 变量 | 六层作用域、单次替换、来源展示、敏感值引用 | 采用原方案与 dp，吸收 c 的来源可视化交互 |
| 请求编辑 | Path、Query、Headers 分区，最终地址实时预览 | 补入 c 的路径参数分区与服务右键配置入口 |
| 工程细节 | 加入执行算法、数据约束示例和分阶段验收 | 吸收 dp 的可执行设计，修正其未闭合约束与编码歧义 |
| 凭据故障 | 不静默降级；保护后端不可用时拒绝持久化秘密，可仅本次使用 | 收敛 dp 的凭据降级待决策项，优先避免不可恢复或意外明文保存 |
| 历史 | 默认只留脱敏元信息，不留完整正文 | 采用原方案与 dp 的安全默认值 |
| 分期 | M1 工程基础、M2 核心闭环、M3 日常交付、M4 进阶能力 | 明确阶段一为 M1+M2，首个完整日常版为 M3，不把全部能力塞入 MVP |

### 1.2 不直接采纳的内容

- 不将“环境显示在树顶端”推断为“一定复制接口”。c 文档自身强调接口列表固定；整合后通过明确的数据关系消除歧义。
- 不采用 SQLite 与散落 JSON 双向实时同步，避免冲突、事务和故障恢复成本。
- 不沿用 dp 草案中变量同时存 `vars` JSON 与 `variable` 表的双份设计；变量统一由 `variable` 实体管理。
- 不直接执行 dp 建表草案：当前环境同项目、目录同服务、根目录重名、变量归属与唯一性需补齐。
- 不照搬“替换完后扫描所有 `{{` 判断缺失”的算法；变量值自身可以包含字面量占位符，不能被误判。
- 不照搬“先替换路径再按 `/` 拆分”的算法；变量中的斜杠应作为参数内容编码，不能变成新增路径层级。
- GraphQL 专用编辑、脚本引擎、跨平台交付均后置评估。首版可发送普通 HTTP JSON，不等于提供完整 GraphQL 调试能力。

## 3. 业务组织模型

### 3.1 项目、服务与接口

```text
商城项目
├── 环境：开发 / 测试 / 预发 / 生产
├── 用户服务
│   ├── 登录相关
│   │   ├── 登录
│   │   └── 退出
│   └── 用户管理
│       ├── 查询用户
│       └── 修改用户
├── 订单服务
│   ├── 创建订单
│   ├── 查询订单
│   └── 取消订单
└── 商品服务
    ├── 商品列表
    └── 商品详情
```

- 一个项目包含多个环境和多个服务。
- 一个服务归属一个项目，包含接口和可选的多级目录。
- 一个接口归属一个服务，可以位于目录下，也可以直接位于服务下。
- 环境不是接口树的父目录，而是项目运行配置的选择项。
- 当前环境按项目记忆，各项目之间互不影响。
- 接口定义不随环境复制，避免多份接口维护不一致。
- 接口树默认展示全部服务；未配置当前环境的服务显示“未配置”，不自动隐藏。

### 3.2 服务与环境配置

| 服务 | 开发环境 | 测试环境 | 生产环境 |
|---|---|---|---|
| 用户服务 | `http://localhost:8081` | `https://test.example.com/user` | `https://api.example.com/user` |
| 订单服务 | `http://localhost:8082` | `https://test.example.com/order` | `https://api.example.com/order` |
| 商品服务 | `http://localhost:8083` | `https://test.example.com/product` | `https://api.example.com/product` |

每个“服务 × 环境”配置项包括：

- 基础地址 `baseUrl`。
- 服务在该环境下的变量、公共 Header 和鉴权覆盖配置。
- 可选的超时、重定向、证书校验配置。
- 启用状态。

接口保存所属服务、HTTP 方法、相对路径、参数和请求体。例如：

```text
所属服务：用户服务
请求方式：GET
接口路径：/users/{{userId}}
```

最终地址由当前环境的服务基础地址、接口路径和 Query 参数组成。

地址处理规则：

1. 使用明确的路径拼接规则，保留基础地址中的网关前缀。
2. 例如 `https://test.example.com/user` 加 `/users/100`，结果为 `https://test.example.com/user/users/100`。
3. 不允许接口路径静默覆盖基础地址的主机或协议。
4. 基础地址限 HTTP/HTTPS，不允许携带用户密码、Query 或 fragment；公共查询参数独立配置。
5. 路径变量、查询参数按所在位置编码，避免重复编码和字符串直接拼接。
6. 服务未配置当前环境地址、被禁用或变量缺失时，禁止发送并显示具体原因。
7. 不允许自动回退到其他环境地址，尤其不能回退到生产。

### 3.3 变量与配置继承

普通变量优先级从高到低：

```text
本次执行临时变量
  > 接口变量
  > 环境下的服务变量
  > 环境公共变量
  > 服务公共变量
  > 项目公共变量
```

- 使用 `{{变量名}}` 引用。
- 未定义变量必须发送前报错；空字符串是已定义值，不能与缺失混淆。
- 第一版不做变量值的递归展开，避免循环引用与隐式求值。
- 只解析原始模板中的占位符，替换值包含 `{{其他名称}}` 时按普通文本处理，不再次展开或误报缺失。
- UI 显示最终值与来源；敏感值默认遮罩。
- 临时变量仅对本次执行生效，不自动写回项目配置。
- Token 等环境相关数据优先配置在环境或环境下的服务范围，避免写死在接口中。

鉴权采用独立的三级状态：

```text
继承 / 不使用鉴权 / 自定义鉴权
```

鉴权查找顺序固定为：

```text
接口 → 环境下的服务 → 环境公共 → 服务公共 → 项目公共 → 无鉴权
```

遇到第一个非“继承”的配置即停止；“不使用鉴权”是显式终止，不继续向上查找。临时变量参与鉴权值解析，但不引入额外鉴权模式层级。配置中只保存模板与秘密引用，不把展开后的凭据写回数据库。

Header 和参数使用列表结构，而不是简单键值 Map：

- 支持重复键、启用状态和排序。
- Header 名称按大小写不敏感规则处理。
- 下层显式配置某 Header 时替换上层同名配置，下层自身的重复项保留。
- 支持显式禁用继承项，不能只提供新增功能。
- 鉴权生成的 Header 与用户填写项冲突时发送前提示，避免出现重复 Authorization。
- API Key 放在 Query 时也做同名冲突检查，不能静默覆盖。
- Query 名称区分大小写；跨层同名覆盖、当前层重复项保留。UI 明确区分“本项不发送”与“屏蔽继承项”。

传输选项的覆盖顺序为“接口 → 环境下的服务 → 环境公共 → 服务公共 → 项目公共 → 应用默认值”；未设置才继承，`false`、空字符串与缺失不能混为一谈。`baseUrl` 只从当前服务环境绑定读取，不参与跨层回退。

## 4. 功能分期

### 4.1 阶段一：最小可用闭环（M1 + M2）

多项目、多环境、多服务、多接口作为基础模型一次建好。

**M1：工程基础。** 建立 Tauri、React、Rust 工程并锁定依赖；打通受限 IPC、SQLite 连接与迁移、数据目录和单实例所有权。验收为应用启动、迁移成功、重复启动唤醒既有实例、不可写目录明确报错。

**M2：模型与请求闭环。** 在 M1 基础上实现下表。敏感变量的保护、遮罩与日志脱敏必须随变量功能一起交付，不能等到后续鉴权 UI 完成才补安全措施。

| 模块 | 范围 |
|---|---|
| 项目管理 | 新建、编辑、删除、项目切换 |
| 环境管理 | 环境增删改、项目级切换、生产环境标识 |
| 服务管理 | 服务增删改、环境地址矩阵、缺失配置提示 |
| 接口管理 | 接口及目录增删改、复制、搜索 |
| HTTP 请求 | GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS |
| 请求参数 | Query、Headers、JSON 和文本 Body |
| 环境变量 | 分层变量、替换校验、来源展示 |
| 执行控制 | 发送、超时、取消、重定向控制 |
| 响应查看 | 状态码、总耗时、响应大小、Headers、正文、JSON 格式化 |
| 持久化 | SQLite 保存、重启恢复、数据库迁移机制 |

验收闭环：

> 创建项目 → 配置环境与服务 → 新建接口 → 切换环境 → 发送请求 → 查看结果 → 保存 → 重启恢复。

### 4.2 阶段二：日常替代能力（M3）

- 表单、multipart 文件上传、二进制请求体。
- Bearer Token、Basic Auth、API Key。
- Cookie 管理。
- 多标签、快捷发送、未保存修改提示。
- 历史记录、脱敏执行快照、重新执行。
- 常见 cURL 导入及导出。
- Postman 基础集合导入，展示兼容性报告。
- 原生项目格式导入导出。
- 本地备份、恢复、历史与响应文件清理。
- 安装版、免安装版、使用说明和交付校验清单。

M3 完成后才形成首个完整日常使用交付版。Postman 基础导入包含在 M3；Postman 格式导出不作为首版承诺，原生格式与 cURL 作为首版导出方式。

不把 cURL 交给 Shell 执行；只解析允许的请求参数，不支持的选项列出提示。

### 4.3 阶段三：测试能力（M4，另行设计）

- 接口串联。
- 响应字段提取为变量。
- 状态码、字段及响应内容断言。
- 集合批量执行与本地测试报告。
- 按实际需要扩展 SSE、WebSocket。
- 评估 GraphQL 专用编辑、受限脚本以及便于 Git 对比的脱敏 JSON 目录导出，均不作为 M1—M3 验收前提。

此阶段另行设计。复杂脚本运行环境、安全隔离及第三方协议不包含在当前实施范围内。

## 5. 界面设计

### 5.1 主界面布局

- 顶部：项目选择、当前环境、环境管理入口。
- 左侧：按服务分组的接口树、搜索、历史入口。
- 中上：请求标签、方法、相对路径、最终地址预览、发送按钮。
- 中部：Path 参数、Query、Headers、Body、鉴权、变量配置；路径参数从路径模板识别，单独编辑，不与 Query 混在一起。
- 中下：响应正文、Headers、Cookies、耗时、大小及错误信息。

默认中文，支持深浅主题。优先保证操作效率，不堆叠装饰效果。

- 服务右键提供“配置各环境地址”入口，与环境矩阵编辑同一份数据。
- 变量旁显示来源提示；最终地址中的敏感参数默认遮罩，复制包含凭据的地址需明确操作。
- 服务节点展示当前环境基础地址，接口选中时展示完整地址，避免长地址挤占整棵导航树。
- Path 参数编辑值写入接口变量或本次临时变量，不另建第三套路径变量存储；同名变量的来源明确展示。
- 编辑区维护草稿与已保存版本，切标签不丢失编辑，关闭未保存内容时提示。异步响应按执行 ID 归属对应请求，不覆盖其他标签结果。

### 5.2 环境管理

采用“服务 × 环境”的矩阵编辑基础地址；展开单元格编辑鉴权、变量及覆盖配置。

- 当前环境固定显示，不隐藏在设置页面里。
- 生产环境醒目标识，并可启用每次发送确认。
- 首次向生产环境发送写请求默认确认；批量执行生产请求必须单独确认。
- 环境切换影响尚未发送的请求；已发出的请求绑定原配置快照。
- 响应结果明确展示实际执行环境，避免与当前选择环境混淆。

## 6. 技术架构与调用链

```text
React 界面
    ↓ 受限 IPC 命令
Rust 本地应用层
    ├── 项目与集合管理
    ├── 环境与变量解析
    ├── 鉴权与敏感信息处理
    ├── HTTP 请求执行
    ├── 历史及响应文件管理
    ├── 导入导出与备份
    └── SQLite 数据访问与迁移
```

职责边界：

- 前端负责编辑、交互和展示，不直接发送目标接口请求。
- Rust 层统一校验输入、读取配置、发送请求、持久化数据。
- 数据库不直接暴露给前端。
- 不为第一版额外启动本地 HTTP 服务。
- 不采用 Redis 或 MQ；SQLite 是结构化配置的持久化事实来源。
- 内存中的请求会话、编辑状态与缓存不能替代数据库，也不能串用环境凭据。

请求调用链：

1. 用户选择项目、环境及接口，生成本次执行 ID。
2. 在短读事务中读取相关配置及版本，连同编辑区提交的草稿形成一致快照；无绑定或绑定禁用则停止。
3. 合并变量、Header、Query、鉴权和执行选项。
4. 校验地址、变量、文件路径；对该次快照完成生产环境确认。
5. 构造只在内存使用的执行配置，并单独构造可持久化的脱敏快照。
6. 原生层发送请求、流式读取响应，按执行 ID 向 UI 推送进度与结果。
7. 按配置写入脱敏历史及响应文件；保存失败独立报告，不把已成功发送的请求改成“发送失败”。

网络等待期间不持有 SQLite 写事务。

### 6.1 组件选型与边界

以下为拟采用组件，M1 验证兼容性并锁定版本；不在本文承诺精确安装包体积、启动时间或最新版本号。

| 领域 | 拟采用组件 | 使用边界 |
|---|---|---|
| 前端构建 | React + TypeScript + Vite | 只构建桌面 UI，不另设 Web 服务端 |
| 编辑状态 | Zustand | 管理标签、草稿和选择状态，不成为持久化事实来源 |
| 文本编辑 | CodeMirror 6 | JSON、请求体及响应文本编辑展示 |
| 异步执行 | Rust + tokio | 网络任务与取消；阻塞数据库访问使用独立工作线程或阻塞任务 |
| HTTP | reqwest | 封装成可测试请求引擎，重定向与凭据策略显式控制 |
| 数据存储 | SQLite + rusqlite（bundled） | 统一数据访问与事务，开启外键，评估并启用 WAL |
| 数据迁移 | 版本化 SQL + schema_migration | 单一迁移执行器；refinery 只作为 M1 评估项，不同时维护两套迁移版本源 |
| 秘密保护 | SecretStore 接口 + Windows 保护后端 | keyring / DPAPI 适配在 M1 验证后选择一种默认实现，禁止静默切换与明文兜底 |
| 打包 | Tauri 打包链 | 安装包和免安装目录包，分别验证离线运行依赖 |

首版不强制引入 TanStack Query：先用 IPC 命令和执行事件管理本地数据及请求状态；后续只有出现明确收益时再引入。JavaFX、Electron 保留为技术背景，不作为当前并行开发路线。

模块边界建议：

```text
项目/集合模块 → 配置仓储
编辑器 → 请求预检/构建器 → HTTP 执行器
                         → SecretStore（仅发送时解密）
HTTP 执行器 → 执行事件 → 响应查看器
           → 脱敏器 → 历史仓储/响应文件
导入器 → 格式校验/ID 重映射 → 配置仓储事务
```

核心对象区分 `RequestDefinition`、`ResolvedRequest` 与 `ExecutionRecord`，分别表示保存定义、内存执行配置和脱敏历史；不能共用一个对象直接序列化落盘。

## 7. 本地数据模型

以下为逻辑实体，具体生产建表 SQL、索引及迁移脚本在实现存储模块时提交；第 15 节补充可在内存库验证的最小关系示例，本次不创建磁盘数据库。

| 实体 | 主要内容 |
|---|---|
| `project` | 项目 ID、名称、创建与更新时间 |
| `project_state` | 项目 ID、当前环境；与定义分离并约束同项目 |
| `environment` | 项目 ID、环境名称、生产标记、排序 |
| `service` | 项目 ID、服务名称、公共配置、排序 |
| `service_environment` | 服务 ID、环境 ID、基础地址、覆盖配置、启用状态 |
| `folder` | 服务 ID、父目录 ID、名称、排序 |
| `request` | 服务 ID、目录 ID、名称、方法、路径、参数、请求体、执行设置 |
| `variable` | 所属项目、作用域、变量名、值或秘密引用 |
| `variable_scope` | 变量容器及其唯一所有者，约束类型、项目归属和引用完整性 |
| `secret` | 凭据保护后的密文或系统凭据引用 |
| `request_execution` | 请求及环境快照、结果、耗时、错误分类、响应文件引用 |
| `schema_migration` | 已应用迁移版本与时间 |

### 7.1 约束与索引

- `service_environment` 对 `(service_id, environment_id)` 建唯一约束。
- 同一项目下环境名称、服务名称分别唯一。
- 服务与环境必须属于同一个项目，使用复合外键或等效数据库约束保证，不能只依赖 UI。
- 目录与接口必须属于同一服务，目录层级不能成环。
- 按作用域和变量名建立唯一约束，避免重复变量定义。
- 接口树索引围绕服务、目录及排序字段建立。
- 历史索引围绕项目、环境及执行时间建立。
- SQLite 连接统一启用外键约束。
- 变量只存 `variable`，服务、绑定和接口的 JSON 配置不再重复保存 `vars`。
- 使用 `variable_scope` 记录项目内的变量归属容器；每个容器只对应项目、服务、环境、绑定或接口中的一种所有者。变量对 `(scope_id, name)` 唯一，`scope_id` 非空。
- `variable_scope` 的所有者必须通过外键、唯一索引与 CHECK 约束实现类型和项目归属校验，不能只存无约束的多态 `scope_id`。
- 当前环境移至 `project_state`，通过 `(environment_id, project_id)` 复合外键验证归属；删除当前环境前在同一事务中清空选择。
- 根目录名称使用单独唯一索引，避免仅依赖含空父目录 ID 的组合约束。
- 删除目录默认不静默删除接口：在事务中将接口移至该服务根目录或用户选定的同服务目录，再删除目录；删除非空服务或项目需独立确认。

### 7.2 事务、迁移与回退

- 项目导入在预校验通过后事务化写入，失败整体回滚。
- 服务配置与关联变量需要作为一个逻辑操作原子保存。
- 删除环境或服务前显示影响范围，不静默破坏关联配置。
- 历史保留脱敏快照，原接口或环境删除后仍能解释历史结果。
- 数据库升级前使用一致性备份，不在活动写入时直接复制主数据库文件。
- 迁移失败停止升级并保留原数据库，不继续启动写入业务。
- 回退优先恢复升级前备份并使用匹配版本的程序，不对数据做不可验证的逆向转换。
- 恢复备份会丢失备份之后的修改，必须提前告知并先保留当前数据副本。
- SQLite 与响应文件不能组成同一个数据库事务，采用临时文件、原子更名和可重试清理流程处理一致性。
- 实施时每个数据库变更同时提供正向 SQL、索引说明、回退脚本或备份恢复步骤，以及数据一致性风险说明。

- 响应正文保存、保留天数、条数和总容量均可配置。
- 系统凭据保护不能防止当前登录用户权限下的恶意程序，也不能替代磁盘加密。
- 免安装目录可以搬移，但受本机保护的凭据不保证跨电脑解密；跨电脑后默认重新配置凭据。

## 11. 关键风险与处理

| 风险 | 处理方式 |
|---|---|
| 请求误发到生产 | 环境固定展示、生产警示、发送确认、禁止环境回退 |
| 写请求重复执行 | 默认不自动重试，发送中防重复触发；人工重发再次确认目标 |
| 取消被误认为服务端回滚 | 明确提示取消仅停止客户端等待，不保证服务端停止处理 |
| Token/Cookie 串环境 | Cookie 至少按项目和环境隔离，默认再按服务隔离 |
| 跨服务登录共享 | 仅在同项目、同环境内明确配置共享组后启用 |
| 跨域重定向泄露凭据 | 不向不同来源自动转发敏感鉴权头；限制重定向次数 |
| HTTPS 校验被长期关闭 | 默认开启，关闭需限定配置范围并持续警告 |
| 大响应卡顿或内存耗尽 | 流式读取、预览上限、落盘上限、磁盘空间不足处理 |
| HTML 响应执行脚本 | 默认文本展示，不在具有应用权限的页面加载响应内容 |
| 不可信导入文件 | 格式校验、资源限制、不执行脚本、不运行 Shell 命令 |
| 配置损坏或迁移失败 | 保留原文件、隔离故障、备份恢复，不静默重建覆盖 |
| 多实例覆盖 | 同一数据目录单写入实例，第二次启动唤醒已有实例 |
| 备份泄露业务信息 | 明确备份包含本地数据，不自动上传；敏感业务正文应谨慎留存 |

错误分类至少包含：变量校验失败、DNS 失败、连接失败、证书错误、超时、用户取消、文件读取失败、磁盘写入失败和数据库错误。

HTTP 4xx/5xx 作为真实响应展示，不混同网络传输失败。总耗时口径统一定义；第一版不展示无法可靠测量的细分耗时。

## 14. 配置解析与请求构建契约

本节吸收 dp 的算法细节并修正歧义。以下为设计伪代码，不是可以直接调用的实现；M2 需用真实 HTTP 测试服务验证客户端最终发送行为。

### 14.1 单次变量替换

```text
resolveTemplate(template, scopes, context):
    tokens = tokenizeOriginalTemplate(template)
    result = []
    for token in tokens:
        if token is literal:
            result.append(renderLiteral(token.text, context))
        else:
            definition = firstDefined(scopes, token.name)
            if definition is missing:
                fail MissingVariable(token.name, sourceField)
            value = definition.secretRef
                    ? SecretStore.resolveForExecution(definition.secretRef)
                    : definition.value
            result.append(encodeVariable(value, context))
    return concatenate(result)
```

- 每个原始占位符只解析一次；不是循环调用字符串 `replace`，不再扫描输出中的占位符。
- 重复使用同一变量时，本次执行复用同一个解析值及来源。
- 缺失检查基于原模板 token，而不是替换后的字符串。
- JSON Body 模式下，变量作为字符串值插入并由 JSON 序列化器转义，不通过裸字符串替换猜测数字或布尔类型。
- 第一版 JSON 模式只支持字符串值中的占位符；不允许占位符直接充当 JSON 结构、键名或裸数字。显式类型参数作为后续增强，首版数字、布尔值直接填写 JSON 字面量。
- Raw 文本模式保持用户选择的原始文本语义，不自动将结果当成脚本或表达式执行。
- Header 解析后校验 CR/LF 等非法值，报错而非发送注入内容。
- 实际值只进入内存执行对象；预览与持久化快照使用脱敏渲染路径。

### 14.2 URL 组装与编码

```text
buildUrl(binding, request, scopes):
    base = parseAndValidateHttpBase(binding.baseUrl)
    pathTokens = tokenizePathTemplate(request.path)
    rejectAbsoluteOrAuthorityPath(pathTokens)
    rejectLiteralQueryOrFragment(pathTokens)
    segments = splitOnLiteralSlashOnly(pathTokens)
    path = renderSegments(segments, scopes,
                          staticMode = preserveValidPercentEscapes,
                          variableMode = encodeAsRawSegmentValue)
    rejectDotTraversalSegments(path)
    url = appendPathKeepingGatewayPrefix(base, path)
    queryItems = mergeEnabledQueryListsLowToHigh()
    url.query = encodeQueryComponentsOnce(queryItems, scopes)
    assert origin(url) == origin(base)
    return url
```

编码契约：

1. 路径模板中的静态 `/` 是分段符，变量中的 `/` 是数据，编码为 `%2F`。
2. 路径模板静态部分合法 `%HH` 视为已编码内容，保留一次；非法 `%` 提示修正，不猜测。
3. 变量和 Query 编辑值视为未编码原值，交给对应编码器处理一次；需要传 `a/b` 就输入 `a/b`，不是预先输入 `a%2Fb`。
4. 静态路径中不允许原样 `?`、`#`，查询参数移到 Query 区；参数值中的这些字符正常编码。
5. 拒绝绝对 URL、`//主机` 形式、反斜杠，以及可能逃离网关前缀的 `.`、`..` 路径段；包括编码后等价的点段。
6. 基础地址的网关前缀不被接口前导 `/` 覆盖；仅规范连接处的斜杠，不能把路径中用户有意的双斜杠全部压缩。
7. 构建阶段保持来源不变；服务器返回重定向属于后续执行策略，不混入地址拼接。
8. 不以普通 URL 相对解析函数的默认行为代替上述业务规则；实现中需要验证最终发到测试服务的路径。

| 输入 | 预期 |
|---|---|
| base=`https://test.example.com/user`，path=`/users/100` | `https://test.example.com/user/users/100` |
| path=`/files/{{id}}`，id=`a/b` | 路径包含 `/files/a%2Fb`，不是两个路径层级 |
| 静态 path=`/files/a%20b` | 保持 `%20`，不产生 `%2520` |
| path=`/files/{{id}}`，id=`a%20b` | 变量按原值编码为 `a%2520b`，UI 解释原值输入规则 |
| path=`/files/{{id}}`，id=`a?b#c` | 参数内容编码，不新增 Query 或 fragment |
| path=`//other.example.com/x` | 拒绝，不替换主机 |
| path=`/../admin` 或包含编码等价点段 | 拒绝，不逃离网关前缀 |
| 缺失变量 `userId` | 发送前提示缺失字段，不回退到其他环境 |

### 14.3 重定向、取消与结果隔离

- 默认不自动重试任何请求；错误信息不得建议用户无条件重发写操作。
- 请求客户端默认关闭自动重定向，由封装层按配置显式处理；若开启，设置跳转次数上限。
- 同来源跳转也需遵守 Cookie 域、路径及安全属性；跨来源跳转默认停止并提示目标，不能自动带着敏感请求体或自定义 API Key 跳转。
- HTTP 方法变化、请求体重放必须明确处理，不默认重放文件流。
- 执行状态按 `待校验 → 发送中 → 接收中 → 完成/失败/已取消` 管理；终态只能提交一次。
- 超时、用户取消和响应完成同时发生时，用同一执行状态裁决，不产生多条互相矛盾的历史。
- 临时响应文件不是历史默认留存：预览会话结束后清理；只有用户启用正文留存才提升为持久响应文件。
- 全量正文达到接收/落盘上限时停止并标注“响应不完整”，不截断后伪装完整结果。

## 15. 数据约束示例与实施检查

### 15.1 核心关系 SQL 示例

以下是用于验证核心关系的最小示例，不是完整生产迁移。省略鉴权、Header、Body、变量容器、秘密、历史和时间字段；不能据此宣称已经完成数据库设计或直接替换已有数据库。

与 dp 草案相比，本示例重点补齐当前环境同项目、目录同服务、根目录重名与接口目录归属。生产迁移在 M1/M2 实现时扩展第 7 节全部字段与约束。

```sql
PRAGMA foreign_keys = ON;

CREATE TABLE project (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL
);

CREATE TABLE environment (
    id INTEGER PRIMARY KEY,
    project_id INTEGER NOT NULL REFERENCES project(id),
    name TEXT NOT NULL,
    UNIQUE (project_id, name),
    UNIQUE (id, project_id)
);

CREATE TABLE project_state (
    project_id INTEGER PRIMARY KEY REFERENCES project(id),
    environment_id INTEGER,
    FOREIGN KEY (environment_id, project_id)
        REFERENCES environment(id, project_id)
);

CREATE TABLE service (
    id INTEGER PRIMARY KEY,
    project_id INTEGER NOT NULL REFERENCES project(id),
    name TEXT NOT NULL,
    UNIQUE (project_id, name),
    UNIQUE (id, project_id)
);

CREATE TABLE service_environment (
    id INTEGER PRIMARY KEY,
    project_id INTEGER NOT NULL REFERENCES project(id),
    service_id INTEGER NOT NULL,
    environment_id INTEGER NOT NULL,
    base_url TEXT,
    enabled INTEGER NOT NULL DEFAULT 1 CHECK (enabled IN (0, 1)),
    UNIQUE (service_id, environment_id),
    UNIQUE (id, project_id),
    FOREIGN KEY (service_id, project_id)
        REFERENCES service(id, project_id),
    FOREIGN KEY (environment_id, project_id)
        REFERENCES environment(id, project_id)
);

CREATE TABLE folder (
    id INTEGER PRIMARY KEY,
    service_id INTEGER NOT NULL REFERENCES service(id),
    parent_id INTEGER,
    name TEXT NOT NULL,
    sort_order INTEGER NOT NULL DEFAULT 0,
    UNIQUE (id, service_id),
    UNIQUE (service_id, parent_id, name),
    CHECK (parent_id IS NULL OR parent_id <> id),
    FOREIGN KEY (parent_id, service_id)
        REFERENCES folder(id, service_id)
);

CREATE UNIQUE INDEX ux_folder_root_name
    ON folder(service_id, name) WHERE parent_id IS NULL;
CREATE INDEX ix_folder_tree
    ON folder(service_id, parent_id, sort_order);

CREATE TABLE request (
    id INTEGER PRIMARY KEY,
    project_id INTEGER NOT NULL REFERENCES project(id),
    service_id INTEGER NOT NULL,
    folder_id INTEGER,
    name TEXT NOT NULL,
    method TEXT NOT NULL,
    path TEXT NOT NULL,
    sort_order INTEGER NOT NULL DEFAULT 0,
    UNIQUE (id, project_id),
    FOREIGN KEY (service_id, project_id)
        REFERENCES service(id, project_id),
    FOREIGN KEY (folder_id, service_id)
        REFERENCES folder(id, service_id)
);

CREATE INDEX ix_request_tree
    ON request(service_id, folder_id, sort_order);
```

### 15.2 生产迁移仍须满足的约束

- 数据库连接外键开关逐连接设置；WAL 配置与备份策略一起验证，不能只在迁移脚本里执行一次就认为所有连接已生效。
- 本示例使用默认限制删除，应用必须先迁移子项或清空选择，再删除父项，整个逻辑操作包在事务内。
- 目录自引用 CHECK 只阻止自己指向自己；多层循环需在事务内用祖先查询校验，后续迁移增加必要触发器，并测试绕过 UI 的写入路径。
- `variable_scope` 对不同所有者采用独立可空外键列及“恰有一个所有者”的 CHECK，每个所有者建立唯一约束；非项目所有者使用含 `project_id` 的复合外键。
- `variable(scope_id, name)` 的 `scope_id` 必须非空；不存在 `NULL` 作用域造成项目变量重复的旁路。
- 变量明文值与秘密引用二选一，空字符串合法；秘密引用的所属项目需受约束，秘密删除不得遗留悬空引用。
- 历史快照与原接口生命周期解耦。删除接口仍可查看脱敏历史；历史索引至少覆盖 `(project_id, executed_at)` 与 `(project_id, environment_id, executed_at)`。
- 原生导入不能绕过上述约束；预校验通过后仍须处理事务中的唯一键、外键和并发修改错误。
- Cookie 持久化能力必须走保护存储与独立清理策略，不能混入普通日志或 JSON 导出。
