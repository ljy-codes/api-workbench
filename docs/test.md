## 评审发现与处理

1. 同 ID 秘密跨项目移动时可能继承旧密文：补同项目继承约束与回归。
2. 关系损坏被 JOIN 静默隐藏：补读取/保存前的完整性校验，损坏时不覆盖原库。
3. 无关项目坏秘密影响发送：增加按请求使用范围解密。
4. 大响应超限持续接收：改为达到接收上限停止，并明确响应不完整。
5. Ctrl+Enter 传播给文本编辑器：前端回归与修复中。

### 复查与历史回归

| ID | 问题/断言 | 本轮处理 |
|---|---|---|
| REG-SECRET-SCOPE | 无关项目坏 DPAPI 秘密不能阻断当前请求 | IPC `send_request` 改用 `load_for_request`，先复现失败再修复 |
| REG-SECRET-MOVE | 同 ID 秘密跨项目移动不能继承旧密文 | 保留同项目继承约束与回归 |
| REG-GRAPH | 损坏关联不能被 JOIN 静默隐藏或覆盖 | store 完整性回归 |
| REG-RESPONSE-LIMIT | 响应达到上限停止接收，不谎报完整大小 | engine 真实回环回归 |
| REG-SHORTCUT | Ctrl+Enter 不插入编辑器换行/重复发送 | 前端回归 |
| V02-HEADER-TEMPLATE | Header 组覆盖须比较展开后的名称，被覆盖默认值不解密 | engine/store 已修复，展开名称、覆盖组和坏密文隔离回归通过 |
| V02-CURL-HEAD | HEAD 导出只用 `--request HEAD` 导致合法无正文响应被 cURL 报错 | 改用 `--head`，导入往返回归通过；HEAD 带正文或 multipart 明确拒绝导出，避免改变语义 |
| V02-AUTH-PROP | 切换同类型鉴权时引用输入框可能显示旧值 | prop 同步、按请求隔离和无效草稿恢复回归通过 |
