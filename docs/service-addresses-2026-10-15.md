# 服务地址统一维护验收

日期：2026-10-15。应用版本保持 1.0.0。

## 需求与调用链

服务地址同时出现在环境矩阵和环境变量里，容易产生重复维护。环境矩阵的 `bindings[].baseUrl` 才是原生请求引擎实际使用的基础地址；环境变量用于请求模板，不会自动更新绑定。Postman/Yaak 导入时可能同时生成绑定地址和原始域名变量。

现在服务地址统一在环境矩阵维护，环境变量页提供直达入口；无引用的重复环境地址按保守规则合并。

## 兼容与安全边界

- 仅合并同项目、同环境、同地址的非秘密环境变量，不改绑定和接口内容。
- 截图中的无协议 IP/端口可匹配 HTTP 绑定；不会推断 HTTPS。业务词不会当作裸主机。
- 遍历同项目所有请求及环境独立配置、服务公共配置和变量值；禁用条目中的引用也保护。
- JSON 正文额外检查解析后的字符串值，保护 Unicode 转义形式的引用。
- 被引用、秘密值、不同作用域、不同环境/项目、异常重复名称均保留。
- 不将展示名称中的占位符误当成可执行模板引用。
- 地址中含凭据、Query、fragment、模板、点段、编码反斜线、控制字符、非法百分号编码或无效 authority 时不合并。
- 合并是纯函数，无变化返回原对象；重复执行稳定，不修改传入数据。
- 编辑变量时焦点离开整行才合并；行内转到秘密复选框时不会删除变量。
- 旧数据加载后仅形成草稿，数据库写入继续复用原保存事务。保存失败仍保留草稿，没有新增 SQL 或迁移。
- 保留的历史地址变量仍为普通变量，不自动跟随矩阵地址变化；界面与使用说明已明确提示。
- Rust 引擎、IPC、版本号、数据库结构及本机真实工作区均未修改。

## 风险与恢复

旧数据中用于人工复制、尚未在任何模板使用的同地址环境变量也符合合并规则；不会将其值写回接口，最终请求基础地址继续由原绑定提供。已引用变量保留原值，因此兼容保留项仍需按其实际业务用途维护。

数据库格式和版本保持不变。合并在内存中完成，保存前原数据库未变；保存后需要恢复被合并的无引用条目时，可通过原有变量编辑器重新添加。单独补回变量不修改现有接口和绑定；需要使用用户自行保存的完整备份时，按原工作区恢复流程操作。
